# AI 写小工具很溜，一进几万行的项目就乱？北大实验室的做法：让 AI 开工前先读懂整个项目，代码改了跟着更新，换会话也不丢。  #姜学长

## 一句话概括
先给AI做“项目索引”，把理解写进仓库，跨会话不丢记忆，大仓库也能持续改对。

## 核心内容
- 背景与问题
AI已能熟练写小工具，但一进到十万、百万行级别的大型代码库就频繁“改A漏B”，且每次换会话还要从头熟悉项目。UP主走访北大“人工智能应用与创新实验室”，请到 AOCI Code 的发起人刘老师，给出一套把“对系统的理解”从对话中搬到仓库内、可持续维护的工程化方案。

- 方案原理：AOCI Code 的“索引压缩 + 持久记忆”
核心是对整个项目做“AI可读索引”。先用模型把每段代码、每个数据库表按约300:1的压缩比转成统一索引（index），70万行代码可压到约300KB。模型先读索引，再开展具体开发任务，实测可召回系统70%~90%的关键信息。此索引用 MCP/CLI 挂到现有智能编程代理之上，成为跨会话的“项目级记忆体”。当你修改代码时，AOCI 会用“指纹”检测定位变更的文件/表，仅对变更部分重压缩，做到 O(1) 增量维护，避免全量重建索引，保证“越改越懂”。

- 案例一：70万行教学底层系统，用业余时间做完
实验室副主任用 AOCI 同时推进五个系统，其中最大约70万行（教学用底层 harness 系统）。工具成本为“200美金包月”，用4个月业余时间推进，折合“约6400元人民币”的云端模型开销，就跑通了大体量项目的持续迭代。这说明：AOCI 把“理解仓库”的难题前置解决，AI改动可持续、跨会话不掉线，从而把开发主矛盾从“会不会写”转为“能不能读懂全局并持续对齐”。

- 适用门槛与收益分层
对于0~5千行的小项目，模型一次就能读完，AOCI 价值不显著；当仓库规模上到10万行以上，AOCI 显著提升“召回全局 + 跨会话连续性”。非专业开发者可借此变“相对专业”，专业开发者更容易向全栈演进。换言之，AOCI 是把“系统级理解”沉淀为工程资产的工具，适合中大型代码库与多人长期演进的产品仓库。

- 边界与未来：受上下文长度限制，但与之共生放大
AOCI 仍依赖模型上下文。当前常用窗口约到1000K规模，70万行项目索引约300K能顺畅迭代；当系统膨胀到200万行，索引或达600K，迭代将受限。随模型上下文扩到2000K~3000K，AOCI 能覆盖更大系统。至于“模型是否会内化这类能力”，短期不太会发生，因为索引是由模型生成、也需由模型消费，仍随上下文增长而外化存在。AOCI 代码已在 GitHub 开源，以便全球验证与共建。

- 实操流程：把AI的“理解”长在你仓库里
安装 AOCI MCP/CLI → 在真实项目一键生成索引 → 与你的编程助手配合使用 → 每次修改代码后，AOCI 发现“指纹变化”并增量更新索引。这样，哪怕换会话、换模型，这份“系统级理解”都固化在仓库里，不再靠临时对话累积。正如视频所言：“工具是租的，长在你项目里的才是你的。”

## 记忆锚点
-【先立碑，再开工】先压缩全仓库成“索引碑文”，AI再动手，改动就不迷路。逻辑：用300:1索引让模型先读全局，再写局部。
-【改一处，响全局】指纹检测变更，O(1)增量更新索引。逻辑：只重压变更文件/表，保持项目级理解持续最新。
-【会话会散，索引不散】把理解写进仓库而非对话窗。逻辑：跨会话、跨模型保留“系统记忆”，不再从零热身。
-【小不必，大必用】<1万行可不急；≥10万行强烈建议。逻辑：上下文难覆盖时，索引显著提升召回与正确率。
-【工具是租的，认知是资产】工具会换，索引常在。逻辑：把“懂项目”沉淀为工程资产，减少人员/会话切换损耗。

## 三大职业视角洞察（重点）
### ① 市场调研 & 用户研究
- 方法迁移：把“研究资料仓库”先做成可读索引（报告、访谈、竞品摘要→索引），让AI沿索引问答与出洞察，减少“只看一角”的偏误。
- 具体做法：建立“研究-索引-问答”三段式流程；每次新增研究只做增量索引（仿AOCI指纹），保证研究记忆跨项目、跨会话延续。
- 避坑启示：避免把长期研究全靠临时对话记忆；把“研究共识”写入团队资产库，减少人变/会话变导致的洞察断层。

### ② 品牌推广 & 营销
- 思路：先搭“品牌索引”（Slogan、资产库、过往投放、受众画像、禁用语），让AI内容生产基于统一记忆，避免风格和信息“改A漏B”。
- 手段：对多渠道内容做增量更新索引；大促/新品时，一键召回全局约束与过往经验，指导文案、素材复用与A/B策略。
- 传播路径：把“品牌记忆”固化为仓库资产，支持跨团队、跨代理商连续协作，减少换人换工具的磨损。

### ③ 电商运营
- 运营策略：构建“商品与政策索引”（SKU、定价、库存、促销规则、售后边界），AI基于索引生成详情页、问答脚本、工单处理话术，减少规则冲突。
- 转化路径：当SKU或促销变化时，仅对变更项做增量更新，保证所有渠道话术与规则同步（仿AOCI O(1)维护），降低用户体验割裂。
- 用户旅程发现：从全局索引回溯高转化要素与踩坑规则，沉淀为“可消费的知识底座”，支撑长期复利。

### ④ 智能硬件 PM（AI时代新定义）
- 能发挥作用的阶段：在需求-架构-固件代码-量产文档等多工种协同处，先做“项目索引”（BOM、接口、约束、CAD参数、固件模块），AI据此产出方案草图、接口自检与变更影响分析，辅助Demo代码快速迭代。
- 边界：ID/MD 创意与关键结构堆叠的物理可制造性判定仍需PM/工程师拍板；复杂安规、材料工艺trade-off与成本责任仍是人主导。
- 工具与职责演变：MCP/CLI 类“索引层”将变为团队标配；PM负责“知识资产化”和跨学科索引治理，AI在固件Demo、接口一致性、变更扩散分析上提效。
