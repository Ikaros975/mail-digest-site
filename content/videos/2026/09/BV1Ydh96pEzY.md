# 阶跃 Step 5 Preview 横测

## 一句话概括
Step5 Preview横测：不抢跑、不掉链，长期高频活儿最省心省钱。

## 核心内容（字数视视频长度而定，上不封顶）
- 背景与结论先行：UP主选了他最常交给Agent的三类“真活儿”——Coding、前端、浏览器自动化，拿Step5 Preview对比GPT5.6 So、gm5.3/gm5.3 Flash、DeepSeek V4.1 Flash，统一用轻量工具集与脚本化评分，盯三件事：效果、时间、成本。结果显示：四家在中等难度的日常任务里几乎都能做完，真正拉开差距的是“速度+钱”。DeepSeek最快最便宜但在Coding错一题；GPT5.6 So稳且快但贵；gm5.3能力接近但成本高些；Step5 Preview整体更均衡、成本在同档中更友好，特别适合长期高频任务。

- 能力与价格：AA（Artificial Analysis）跑分中，Step5 Preview 44分，GPT5.6 So 47分，gm5.3 45分。价格上Step5官方标价：输入每百万token约7元、缓存命中约0.35元、输出约12–20元；但关键在“套餐”：最高档699元/月给40000 million credit，折合约57倍的“真实用量”放大。在real API pricing的口径下，Step5 Preview落在“能力-价格”帕雷托前沿，每百万token不到0.03元人民币。因太划算套餐已限售、每天限量开放。

- 评测方法论：为了“只测模型真本事”，UP主做了几件事——
  1) 任务封闭化：固定输入、明确完成条件，程序脚本判分。
  2) 工具极简：用“派（Pai）”搭轻量harness，仅4个工具，避免“框架代劳”掩盖模型真实力。
  3) 反作弊：禁止联网、剥离git历史、隐藏测试集，脚本还会检查是否偷看目录/联网。
  4) 出题-做题分离：出题Agent先用答案自查评测标准，再让做题Agent盲测，防“同人出题同人做题”。
  5) 选“吞token”的真活儿：编码、前端、E2E浏览器操作，既考逻辑也考工程执行。
  这套流程也由Agent先起草，UP主人工核对后再让Agent写脚本与环境，最终他手动一键跑测。

- 案例一：Coding（开源项目“派web”6个真实commit：3个新功能+3个bug修复）
  - 约束：从改动前版本导出干净代码、无git历史、断网、隐藏测试、会话记录审计。
  - 结果：DeepSeek错1题，其它三家全对。DeepSeek最快17分钟/$0.32；GPT5.6 So 39分钟/$4.46最贵；Step5 Preview 45分钟/$1.36，成本约为GPT的三分之一左右；gm5.3表现接近。细节上，Step5爱“自写测试”，单题最多写29条，GPT每题写3–6条。
  - 结论：在中等难度编码题上，四家只差“稳/快/省”的取舍；Step5倾向“多做校验”，带来更低错率与更高token消耗。

- 案例二：前端页面（根据设计稿+每日营销数据，做可按日/周/月切换的营收看板）
  - 评分：100分制，视觉20分、功能交互80分；含单元测试+端到端（E2E）测试；有“换一份新数据”的反硬编码检查，埋闰年、营收为0、整月缺失等坑。
  - 结果：四家功能全部满分；差别在视觉。Step5 Preview视觉分最低（搜索框未居中、数值位置偏差），因此总分相对低。时间/成本差距大：DeepSeek约3–4分钟；GPT约7分钟；gm5.3 Flash约21分钟；Step5 Preview约48分钟且成本最高（约$1.3）。
  - 过程洞察：Step5前18分钟不写代码，先用Python把设计图切成30多张小图、测像素/取色/量尺寸，再开写；之后又花20分钟写42项检测，覆盖12种筛选组合，多次截图回对设计稿。全程109轮对话、125次工具调用、看图36次；对比GPT仅12轮/20次工具调用/看一次图。可见Step5是“反复核对的严谨新人”，GPT像“经验老手一次成型”。

- 案例三：浏览器自动化（在自建旅游预订站完成真实预订流程）
  - 任务：9月25日上海→深圳，选最便宜直飞；酒店选满足条件且离会场最近；乘客信息自取；不买保险；发票开电子普通发票。
  - 干扰：全屏cookie弹窗、促销弹窗、广告遮挡；相近但易误选的信息；错误默认值等18项检查点。
  - 结果：四家18项全对。DeepSeek约2.3分钟/$0.05最快最省；GPT约3分钟/$0.71；gm5.3 Flash约11分钟/$0.07；Step5 Preview约6.7分钟/$0.22。  
  - 结论：在标准化强的“流程型任务”，主流模型已高度可靠；再比，主要是“谁更快/更便宜”。

- 总体账本与定位：三项合计——Step5 Preview 99分钟/$2.89（约21元）；gm5.3（后两项用Flash）97分钟/$3.89；GPT5.6 So 49分钟/$5.82；DeepSeek 23分钟/$0.44。跑分上Step5接近gm5.3与GPT5.6 So，但成本更低；对比DeepSeek，虽贵一些但分数高5分且本轮无错题。吐字速度实测≈100 token/s。结论：Step5 Preview是一只“均衡型长跑选手”，最适合“长期高频、要稳要省”的用法位，这也解释了它为何落在能力-价格的帕雷托前沿。

## 记忆锚点（3-5条）
- 【均衡长跑】“不抢头名，跑完全程”——Step5 Preview在中等难度真活儿里稳定完成，成本优于同档，适合高频长跑任务。
- 【严谨新人】“先量尺再下刀”——Step5倾向先切图量尺、写自测，多轮校验换来更稳结果，代价是时间与token。
- 【评测铁律】“出题做题要分家，断网盲测靠脚本”——封闭输入、隐藏测试、禁联网、脚本判分，才能测出模型真功夫。
- 【帕雷托位】“一分价钱一分智力”——按套餐折算的真实单价下，Step5在能力/价格曲线上站到最优边界。
- 【流程无敌】“有流程就有答案”——在浏览器标准流程任务上，四家18/18全中，差距只剩“谁更快、谁更省”。

## 关键要点（3-6条）
- 要点一：用“真活儿”+脚本化打分比跑分榜更可信
  - 原文引用：「所有的任务都是封闭式……最终的结果会由程序脚本去判断，尽量不靠人去主观打分」（中段）
  - 案例还原：三类任务分别设置固定输入与明确成功标准；剥离git历史、禁联网，隐藏测试集；脚本除判分还审计是否联网/读目录，最大限度防作弊。
  - 解读：适合团队自建评测基准，能复用到生产验收。

- 要点二：出题Agent与做题Agent必须隔离
  - 原文引用：「出题的agent跟做题的agent一定要分开……不然就有作弊的嫌疑」（中段）
  - 案例还原：出题Agent先跑标准答案校准评测指标后，做题Agent才在“盲测”环境做题；避免模型“见过答案”或暗合打分脚本。
  - 解读：适合自动化评测/竞赛/内部Benchmark流程。

- 要点三：Step5的“严谨型策略”=更稳但更慢
  - 原文引用：「他用Python把设计稿切成30多张小图……再开始写代码……又花了20分钟来写测试，一共做了42项的检测」（中段）
  - 案例还原：前端任务中，Step5总计109轮对话/125次工具调用/36次看图；对比GPT 12轮/20次/看一次图。视觉分略低但功能全满。
  - 解读：适合质量优先、可承受较高时延与token的场景。

- 要点四：中等难度日常任务已“难不倒”主流模型
  - 原文引用：「四个模型基本能全部完成我设计的任务……日常任务已经很难难倒现在的大模型了」（结尾）
  - 案例还原：Coding除DeepSeek错一题外全对；前端四家功能满分；浏览器18/18全对。真正差异体现在时间与成本的量级。
  - 解读：企业落地该聚焦“性价比/时延/SLA”，而非“能不能做”。

- 要点五：Step5坐在能力-价格的帕雷托前沿
  - 原文引用：「按照这个算法……Step5的preview正好是在能力跟价格这个帕雷托的最优边界上……每百万token不到三分钱人民币」（前段）
  - 案例还原：通过“套餐折算单价”的real API pricing方法，统计各家月费/可用量得真实单价；Step5因57倍用量倍率脱颖而出，但套餐现限售。
  - 解读：采购与成本管控可参考“真实单价”，别只看官方标价。

## 三大职业视角洞察（重点！）
### ① 市场调研 & 用户研究
- 新洞察/方法论：
  - 用“封闭式真任务+脚本评分+反作弊”替代主观打分，得到可复现、可同比的模型评测。
  - 以“最常见真实任务（吞token）”做分层测试，更贴近业务落地的收益-成本曲线。
- 可借鉴的调研方法：
  - 套餐折算的“真实单价”法（real API pricing）去建立“能力-价格帕雷托”图，指导模型选型。
  - 将出题/做题Agent分离，先用标准答案自检评测规则，再盲测，避免过拟合评分脚本。
- 被揭示的坑：
  - 只看官方标价会高估成本；只看跑分会忽视“速度/费用/SLA”。
  - 工具/框架过重会“掩盖”模型真实能力，误判可用性边界。

### ② 品牌推广 & 营销
- 新思路/案例：
  - “严谨型工作流”是可讲述的卖点：Step5通过多轮校验、自写测试，传达“稳、可托付”，适合B端长期任务背书。
  - 用“帕雷托前沿”叙事构建“性价比领导者”定位，辅以限售节奏制造稀缺感与口碑扩散。
- 值得研究的传播路径：
  - 用真实对比数据（时间/成本/功能达成率）做内容增长，避免空洞广告语。
  - “工程透明化”传播（公开工具数、对话轮次、测试覆盖）提升专业感和信任度。

### ③ 电商运营
- 可参考的运营策略/案例：
  - 将关键流程（下单、改签、退款等）标准化为E2E脚本，持续回归；主流模型已能稳定全通。
  - 任务型RPA+LLM混合：在高干扰页面（弹窗、广告、错默认值）下，模型仍能达成目标，适合高峰期自动化分流。
- 转化路径/用户旅程新发现：
  - “可被脚本稳定完成”的流程，也最适合做AI引导&托管；运费/发票/保险等默认项需显式检查，避免错扣增成本。

### ④ 智能硬件 PM（AI时代新定义）
- 能力发挥阶段：
  - 需求—>原型验证：让模型先产出“测试先行”的规格（如Step5自写测试/多轮校验），再落ID/MD方案更稳妥。
  - 早期交互验证：借E2E脚本做固件/应用的人机流程回归，提前发现“弹窗/遮挡/默认值”类可用性问题。
- 边界：
  - ID设计/MD堆叠的创意与工程权衡仍需PM主导；AI能做方案穷举与自测，但“取舍”与“场景化体验”要人拍板。
  - 电子设计demo阶段，AI可协助BoM校对、接口一致性检查与脚本化回归，但硬件容差、安规、成本打样需人工决策。
- 工具/流程信号：
  - “出题/做题分离+隐藏测试+禁联网”的工程化评测会成为AI产品线标配CI。
  - 以“真实单价”纳入PRD评审与成本模型，模型选型=体验/成本/SLA三角优化的新职责。

## 精彩原句摘录（2-5条）
- 「出题的agent跟做题的agent一定要分开……不然就有作弊的嫌疑」（中段）——把评测“公平与可复现”原则钉死，是所有AI评测的底座规则。
- 「四个模型功能全部都是满分，差距只是在视觉分数上」（中段）——说明在标准化强的前端功能面，主流模型已趋同，后续比的是“质感/效率/成本”。
- 「真正的差距呢这次看来是在时间跟成本上」（结尾）——点明当下AI落地的核心优化变量：不是“能不能做”，而是“多快多省”。
- 「Step5更像一个反复核对的新人，GPT像一个一次就能做对的老手」（中段）——生动刻画两种推理风格，帮助选型时匹配业务偏好（稳 vs 快）。
