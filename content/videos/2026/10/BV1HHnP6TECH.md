# 2026年，我是怎么用知识库的？

## 一句话概括
自用用Obsidian+VICKI，他用RAG+MCP，把知识握在自己手里还能进别人工作流。

## 核心内容
- 背景与总体策略：UP主两年前已系统讲过个人知识库与RAG，如今方法更新但底层原则未变——「资料得掌握在自己的手里」。他将知识库分为“自己用”和“给别人用”两类，因使用者不同而采用不同技术路径。与两年前不同的是，如今模型上下文窗口更大，原文可直接放更多，但他强调「长上下文也不是万能的」：当资料量超出窗口或希望降低输入成本，仍要靠检索；且“装得下不等于推理精度稳定”。结论：上下文+检索并用，技术更新但数据主权不变。

- 自用知识库的两步法（检索与结构并重）：
  1) 使用 Obsidian 原生检索：UP主指出 Obsidian 的「精确检索」可将关键词、笔记结构、标签与属性组合，精确度高。关键是让 agent 能调这个能力——「官方出了CLI…以后要去这个知识库里查资料的时候，优先使用OBSIDI CLI」。做法即是配置好 CLI，并在 agent 侧设定优先调用。结果：在长上下文并不可靠时，以结构化检索缩小范围、降低输入量与成本。
  2) 建立“VICKI”地图：他为知识库建立一套“VICKI”，以更结构化方式展现“整个库有什么内容”“反复谈到的概念主题”“过去讨论过的观点及其关系”。这不仅是目录，还把“已整理过的东西”沉淀下来，后续“有了新内容还能继续更新进去”，让积累“不断生长”。对 agent 而言，VICKI「就相当于一张地图」，告诉它库是干嘛的、已有何整理成果、去哪找原文，显著提升检索效率。UP主表示这套方法早在“new type os”里实现并长期使用，效果不错。

- 给别人用的知识库（让你的内容进入他人的工作流）：UP主在网站“new type点pro”发布过往帖子、文章、视频脚本与课程，原本是“给人看的”。为让用户把这些内容给到 A卷/agent 做参考，他把网站内容“整理成了一个知识库”，采用两项技术：RAG 与 MCP。RAG部分：将文字切块建立向量索引，支持语义检索，同时网站也做关键词匹配，双通道助力找到相关资料。接入部分：用“new type m cp”，提供“搜索内容、读取原文、浏览目录”等功能。会员给 A卷装上这个 MCP 之后，就能在处理自己的问题时“按需调用我的内容作为参考”。效果：原为“给你看”的内容，变为“能进你的工作流、帮你做事”的外部知识库。

- 方法选择的准绳与不变的底线：UP主归纳选择依据——「主要看资料放在哪里、谁来使用、以及agent怎样才能找到并读懂它」。策略可随着模型能力、接口形态演进而变，但底线不变：「自己的积累要留在自己的手里，也要能持续地发挥作用」。

## 记忆锚点
-【钥匙在手】“数据在手，工具常新”：先保管原始资料，再选模型/agent，方法可变，积累常在。
-【长桶配漏斗】“上下文再长，也要检索漏斗聚焦”：装得下不等于精度稳，先检索再推理更省钱省错。
-【先画地图】“有了VICKI，agent不迷路”：先把概念、观点、关系结构化，检索才快、回答才准。
-【搭桥入流】“MCP是你的知识到他人工作流的桥”：RAG+关键词配接入能力，内容从“给你看”到“替你干”。

## 关键要点
- 资料主权不变
  - 原文引用：「资料得掌握在自己的手里」「方法可以变，但是自己的积累要留在自己的手里，也要能持续地发挥作用」
  - 案例还原：UP主把自用资料全部放在自己可控的知识库中，不依赖单一模型或工具；即使更换模型/agent，已有积累可直接复用，避免“换工具从头再来”。
  - 解读：避免厂商锁定，长期复用沉淀。

- 长上下文≠不要检索
  - 原文引用：「长上下文也不是万能的…上下文装得下，也不等于模型就能…保持同样的检索和推理的精度」
  - 案例还原：虽然现在模型上下文更大，他仍“靠检索”控制输入规模与质量，防止在海量上下文中推理精度下降，提高稳定性与成本效率。
  - 解读：在大文本场景中保精度、降成本。

- Obsidian 原生检索 + CLI 让 agent 用起来
  - 原文引用：「它的精确检索…可以把关键词笔记结构、标签和属性…组合起来使用」「官方出了CLI…优先使用OBSIDI CLI」
  - 案例还原：利用 Obsidian 的结构化检索（关键词+结构+标签+属性），配置官方 CLI，令 agent 先检索再读原文，精确定位资料后再调用模型处理。
  - 解读：以结构化检索作“前置过滤”。

- VICKI 把知识地图化
  - 原文引用：「我给我的知识库建了一套vi…能以更加结构化的方式去展现…不只是目录…把过去讨论过的观点以及它们之间的关系都整理出来」「对于A卷来说，VICKI就相当于一张地图」
  - 案例还原：UP主系统清点库中主题与概念、沉淀观点与关系，形成可持续更新的“地图”，agent据此定位主题、查找原文，避免每次“从头再来”，检索效率显著提升。
  - 解读：结构胜于堆砌，复用沉淀。

- 给别人用：RAG+关键词+MCP 入工作流
  - 原文引用：「把文字内容切块建立向量索引…网站也会做关键词的匹配」「new type m cp提供了搜索内容、读取原文、浏览目录…会员给A卷装上这个MCP之后，就能调用」
  - 案例还原：网站端统一存放帖子/文章/脚本/课程，构建向量索引配合关键词匹配；以 MCP 开放搜索/读取/目录，会员在自己 agent 中按需调用，内容从“给你看”转为“帮你做”。
  - 解读：内容服务化，融入用户流程。

## 三大职业视角洞察（重点）
### ① 市场调研 & 用户研究
- 方法论启发（解读）：先“画地图再检索”。用 VICKI 式结构化梳理研究主题、概念与观点关系，减少重复检索；先用结构化检索（类似 Obsidian 组合条件）缩小材料池，再喂给模型分析。
- 可借鉴做法（解读）：建立自有知识库并配检索优先策略；当材料超长时，仍以检索漏斗控量提质，避免盲放长上下文。
- 暗坑提醒（解读）：长上下文不保证精度稳定；应以结构化标签/属性打底，保证可检索、可溯源。

### ② 品牌推广 & 营销
- 新思路（解读）：把“内容资产”产品化为“外部知识库”，通过 RAG+关键词增强可发现性；用 MCP 作为“接入层”，让用户的 agent 主动来调内容，内容从“被阅读”变为“被调用”。
- 传播路径（解读）：在网站端统一内容与权限管理，提供搜索/读取/目录接口，降低接入摩擦，成为用户工作流的一部分，提高复访与粘性。

### ③ 电商运营
- 运营策略（解读）：将商品知识、售后FAQ、运营SOP等沉淀为可检索的库，先结构化（类似VICKI地图），再通过检索优先策略提升答复准确率与效率。
- 转化路径（解读）：以 MCP 式“接入能力”把内容嵌入客服/运营 agent 流程，实现“按需调用资料”辅助转化与售后。

### ④ 智能硬件 PM（AI时代新定义）（解读）
- 能发力的阶段：在需求与知识沉淀阶段，先用“VICKI式”结构化梳理概念/方案/关系；以检索优先策略为评审、复盘提供可溯源资料；通过 MCP 接入外部资料库作为参考基线。
- 边界：PM 仍需亲自定义“地图”结构与关系、判定资料权威性与适用性，AI负责检索与初步归集。
- 信号：内容统一、检索增强、可被 agent 调用的“接入层”，正在成为知识型工作的基础设施。

## 精彩原句摘录
- 「资料得掌握在自己的手里」（开头）——点明方法可变而资产不变的底线，最具长期指导意义。
- 「长上下文也不是万能的…上下文装得下，也不等于模型就能…保持同样的检索和推理的精度」（中段）——破除“长上下文=万金油”的误解，是工程化落地的关键提醒。
- 「对于A卷来说，VICKI就相当于一张地图」（中段）——用“地图”形象化解释结构化沉淀的作用，直观好记。
- 「现在我想让他们也进入你的工作流，帮你做事」（中段）——从“给你看”到“替你干”的角色跃迁，点出内容产品化与接口化的价值。

## 适合人群
- 想用 agent 提效、却总被“长上下文”和“乱库”拖累的个人与团队。
- 有稳定内容产出、希望把内容变成“可被调用的服务”的创作者与企业。
