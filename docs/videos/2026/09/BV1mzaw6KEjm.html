赚钱的机会，为什么总被自己分析没了？

B站 · 课代表立正 · BV1mzaw6KEjm
cyan

一句话概括

别把机会分析死：放下自我、认真入戏，先做再说。

blue

核心内容

  • 背景与问题定位：UP 主两周前提出“做个不 productive 的 role model（君子不器）”，却很快掉进误区：为了“不 productive”，他否定了一切看似“有效率”的活动，转而刷短视频，结果“看的时候开心，看完很 miserable”。这段亲身试错说明：拒绝“生产力崇拜”不等于拒绝有意义的投入。正确打开方式是用“有意义的非功利活动”（如骑山地车、健身）替代无意义的消耗，并用“循序渐进”的节奏建立新习惯——先做到一周一天，再扩展到两天，让“不 productive 但有意义”的时段稳固下来。

  • 关键结论：不要以“否定 productive”为目的；要以“填充有意义的生活”为路径，渐进改变。

  • 核心观点一：成功无技巧，唯一的“技巧”是认真。UP 引述“看本质”课程的要点：面试、找工作、做事都没有奇技淫巧，关键在于“把自己带入问题场景，放下 ego，沉浸式解决问题”。“把面试看成收费站而非终点”——通过收费站只是开始，真正检验在“上路之后能否解决真实问题”。

  • 案例：甄子在从 Meta 跳槽 Netflix。背景：竞逐顶级岗位；过程：他与 AI 多轮对话，模拟 Netflix 真实业务情境，联动模型与 web code 复刻问题现场，梳理条件成立与否，推演完整解法；结果：面试官震惊其准备度与贴近一线事实，“你不仅想到了我们正在经历、外界未知的问题，还把解法想透了”，最终高度认可。这是“认真”的直观样本：不是背题库、优化简历，而是提前入戏，拿出面向真实业务的方案。

  • 关键结论：别把时间花在“表面功夫”（背题、包装人设）上；沉浸问题本身，才是穿越面试门槛、在岗表现持续优秀的根基。

  • 核心观点二：你看不见机会，多半是“想自己太多”。UP 给出当日群聊里的“HOA 软件”现场案例。背景：某人看到社区物业（HOA）用一款软件，每户月费 2 美元、300 户合 600 美元/月，自觉一周内可用 AI 做出替代品，且更好更便宜。过程：还没做就开始预设失败：“做出来也会被更便宜的产品替代；那不值得，我还是打工吧。”结果：项目在脑中夭折，零验证、零对话、零交付。

  • 深度复盘：他没搞清三件事——1）需求与市场：一个 HOA 背后可能是上百个类似组织，市场或远大于想象；2）信任与采购：B 端购买常不以“更便宜”为唯一要素，背后是信任、合规、风控、迁移成本；3）真正难点：不是“能否一周做完”，而是“能否被采纳”。把心思放在“我会不会被替代”，等于提前制造了一个还不存在的问题。结果就是“机会被自己分析没了”。

  • 关键结论：行动前置、难点前置——先做出最小可用版（MVP）、先对话目标用户、先跑一次真实采购/试点，再谈竞争与规模。

  • 核心观点三：把心思放在事上，而不是放在自己身上。UP 指出，很多人把大量时间耗在“无意义的工作与内耗”上，例如为开会而开会、下午忙完产出极少；而高效的人“每做一件事都非常到位”，因为他们关注的是“产出”和“解决问题”。当你真正沉浸在要解决的那个问题上，反而不会自我设限（“我行不行”）、也不被评价恐惧牵制（“别人会怎么想我”），于是更容易 make progress。

  • 关键结论：问题导向替代自我导向；产出导向替代过程导向。外部机会之所以“对多数人不可见”，常常只是因为注意力被自我叙事和无效流程吞噬了。

记忆锚点

  • 【收费站不是终点】“面试是收费站，上路才是考场” + 逻辑：别沉迷面试技巧，提前入戏到真实场景，验证自己能否解决在岗问题。
  • 【先做再担心】“先落地一米，再眺望一公里” + 逻辑：用 MVP+用户对话验证需求和采纳，再评估竞争与规模，别把机会分析死。
  • 【事心互换】“把心从自己身上挪到事上” + 逻辑：放下自我与评价焦虑，专注问题本身，产出自然提高，机会自然显形。
  • 【反功利也要有意义】“拒绝效率，不等于拥抱空耗” + 逻辑：用有意义的非功利活动替代无意义消耗，循序渐进建立新节奏。
  • 【认真即“唯一技巧”】“无技巧之技：极致认真” + 逻辑：沉浸式理解问题、条件、限制与解法，胜过一切表面包装。

关键要点

  • 要点一：唯一技巧是“认真”
  • 原文引用：「没有技巧……唯一的技巧呢就是认真。」（中段）
  • 案例还原：甄子在跳槽 Netflix 的准备不是背题，而是用 AI+代码复刻 Netflix 的业务问题，推演条件、方案与权衡；面试时直击“他们正在发生但外界不知”的难题，获得高度认可。

  • 解读：面试/做事都如此——真实问题场景里的“可用解”最有说服力。

  • 要点二：面试是收费站，不是终点

  • 原文引用：「你要把面试看成一个高速公路的收费站，而不是要把它看成终点。」（中段）
  • 案例还原：UP 强调，若靠包装混过收费站，最终仍会在“高速上”暴露：做不喜欢或做不好的事、很快被淘汰；把关注点放在“能否在真实岗位解决问题”，才不致走偏。

  • 解读：把“过关”转为“过关后能活好”，择业更稳、成长更快。

  • 要点三：机会常被“自我叙事”扼杀

  • 原文引用：「这是为什么我会看到这个世界上充满了机会，但是这些机会对于大多数人来说似乎就看不到。」（中段）
  • 案例还原：HOA 软件机会：还没验证就先想“会被更便宜替代”，忽略了市场规模、信任和采购流程等真正难点，最终选择放弃，零试错、零接触用户。

  • 解读：把“担忧列表”变成“验证清单”，才能从想象走向市场。

  • 要点四：把心思放在事本身

  • 原文引用：「你的心思在不在这件事本身上，还是在一些乱七八糟的别的东西上。」（中段）
  • 案例还原：UP 对比两类人：一类反复开会产出稀少；另一类每次都有到位结果。差异来自是否以产出为目的、是否沉浸问题本身，而非“为了开会而开会”。

  • 解读：用“结果定义任务”，逆推行动与会议，减少无效忙碌。

  • 要点五：不 productive 的正确姿势

  • 原文引用：「想要做到不productive这件事，不能直接的去否定做productive的事，而是要去找一些另外的事情去填充自己的生活。」（前段）
  • 案例还原：UP 为避免“productive”而刷短视频，短暂快乐、事后空虚；改为去保养山地车、计划运动，并用“每周从一天开始”的渐进法，逐步建立“有意义的非功利时间”。
  • 解读：反功利也需设计路径：替代+渐进，才可持续。

三大职业视角洞察（重点）

gold

① 市场调研 & 用户研究

  • 新洞察：从“自我驱动”转为“问题驱动”。别先问“我行不行/会不会被替代”，而是先问“用户现场到底怎么用/为什么不用”。
  • 可借鉴方法：
  • 场景模拟+AI 辅助：像甄子在一样，用 LLM 推演业务流程、边界条件、失败模式，生成假设清单。
  • 最小可行验证（MVP）：做最小版本给到真实用户/采购方，关注采纳门槛（信任、迁移、合规）。
  • 采购旅程访谈：对 B 端，专访决策人/使用人/IT/法务，厘清非价格因素的决定权重。
  • 预案式调研：把“担忧”转为“需验证假设”，逐项外部验证。
  • 常见坑：把价格战当成唯一变量；沉迷竞品功能对比，忽略采纳与集成成本。
red

② 品牌推广 & 营销

  • 新思路：热领域+独特立场。处在“hot”赛道（如 AI），用“高超的弃绝”（说不的能力）建立品牌差异：不做花哨包装，做能解决真问题的内容资产。
  • 可实践路径：
  • 内容即证明：用“问题复盘+可运行 Demo/数据”取代“口号”。让受众看到你“已经在他们的问题里”。
  • 漏斗观重构：把“投放/引流”当收费站，后端必须有“真实价值交付”的高速路（成功案例、可验证 ROI）。
  • 信任构建：B 端营销重在“可采购性证据”（安全、集成、合规、迁移计划），而非单纯更低价。
  • 传播路径：以案例为核心串联邮件、白皮书、演示视频与技术博客，形成可验证的“认真度”叙事。
cyan

③ 电商运营

  • 可参考策略：
  • 动手先行：快速上新 MVP、投小流量做 A/B，先看转化与留存，再扩 SKU/活动强度。
  • 关注采纳壁垒：不仅盯价格，更多盯信任与体验迁移成本，设计“无风险试用/迁移助手/售后 SLA”。
  • 用数据“盯事不盯人”：以产出指标（下单、复购、客诉闭环时长）倒推日常运营动作，淘汰“为活动而活动”。
  • 新发现：很多“分析”在验证前毫无意义。把“担心会被更便宜打掉”转化为可测的价格敏感度实验和差异化价值证明。
blue

④ 智能硬件 PM（AI 时代新定义）

  • AI 能发挥作用的阶段：
  • 需求发现：用 LLM 重放用户场景、生成 use case 与边界条件列表。
  • 方案推演：用仿真/生成式工具评估 ID 方案、MD 堆叠可行性，提前识别干涉/散热/装配风险。
  • 电子设计 Demo：用 AI 协助生成原理图初稿、固件样例、测试脚本，快速出功能样机验证“事是否可成”。
  • 边界：问题定义、风险取舍、合规与安全仍需 PM 主导；AI 难以替代跨团队沟通、供应链博弈与最终责任判定。
  • 信号与流程变化：从“文档驱动”转为“可运行原型驱动”；从“汇报技巧”转为“验证强度”；岗位画像从“项目推进”升级为“问题发现与可验证解的策划者”。

适合人群

  • 求职者、转岗者、初创团队与产品人：想提升“从分析到落地”的速度与质量。
  • 深陷“忙而无果”的职场人：需要从“自我叙事”切回“问题场景”，用可验证产出破局。
  • 用 AI 做实事的 Builder：希望把 AI 从“会做题”升级为“会出题+会落地”的实践者。
