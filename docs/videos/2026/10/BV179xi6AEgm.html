核心内容

背景与模型定位。 UP主介绍，百度文心团队发布专门用于OCR与文档解析的模型 Unlimited-OCR-2，已登上 Hugging Face 趋势榜。模型拥有33亿参数，bf16权重文件约6.7GB。最大亮点是通过稀疏注意力降低长文档解析的计算开销，重点解决跨页段落表格衔接、阅读顺序等难题。它采用视觉语言模型架构，能提取文档图片里的文字、公式、表格，还能恢复结构——识别标题层级、版面位置、阅读顺序。最值得关注的能力是能把几十页上百页文档连续解析并保留跨页段落、表格和版面结构，可用于论文资料整理、扫描书籍数字化、企业文档处理、搭建RAG知识库等场景。UP主特别交代：第一版 Unlimited-OCR 他实测体验”非常差”，所以当时没发测评视频；这次二代能力”确实有了非常大的提升”，才有了这期本地部署实测。

部署与工具链（案例：自建Web UI）。 UP主把模型部署在 RTX A6000 设备上，并让 codex 开发了一个易交互的 Web UI：界面实时显示 GPU 计算利用率、显存、内存、CPU 信息；左侧显示原始文件，右侧显示解析后内容，还显示输入页数、输出token、首内容token等待秒数、任务耗时、原始输出字符数等参数，可预览 Markdown、查看原始输出（类似HTML的标记格式）、查看请求详细记录。他把这个 Web UI 项目开源到 GitHub，又把本地部署方式固化成一个 skill 并 push 到 GitHub 仓库，方便用户为自己的 codex、workbody、cloud code、workbot 等 AI agent 安装该 skill 来本地部署模型。

实测案例链（难度逐级加码，结果全部成功）。 1. 单页模糊扫描书页：图像非常不清晰，仍成功解析，连图中公式也解析出来，文字无错误；耗时2.6秒，原始输出760字符。 2. 十页多页PDF：GPU占用达88%；任务耗时39.7秒；第一页、第二页、最后一页提取内容完全正确，带索引序号的内容也成功提取。 3. 九份合成复杂PDF（双栏研究报告）：双栏排版、含表格与图表，成功按栏提取，图表精准提取，表格与页码也成功提取，最后一页完全正确——说明能识别复杂排版。 4. 多种复杂表格PDF：结构复杂的表格严格按照原表格结构输出，第二份表格及剩余表格均正确。 5. 公式+表格+流程图混合PDF：复杂公式（含第二页复杂公式）、表格、流程图提取均正确。 6. 非常不清晰的PDF扫描件：排版也不好，最不清晰的最后一页识别完全准确，小字也无问题。 7. 竖排繁体字古书：文字与标点完全正确，但输出顺序是从左向右，而原书是从右向左——最后一句被放到了第一句位置。UP主给出解法：用代码对提取内容重新排序即可实现从右向左输出。 8. 中日韩混排双栏PDF：单页含日语、韩语、中文且分两列排版，三语部分提取均完全正确。

关键结论。 通过多个案例测试，这款模型在OCR与文档解析方面能力”确实有了非常大的提升”：复杂文档、多语言文档、复杂排版都能轻松提取并保持原有格式。唯一暴露的短板是竖排古书的阅读顺序（右→左）需要后处理修正。

记忆锚点

【八级台阶】从糊书页到三语混排，八道关卡一级级加码，关关通过只剩”古书倒着读”一关要补丁——难度递增式实测法本身就是最好的评测框架。 【2.6秒一页】单页扫描2.6秒、十页PDF 39.7秒，GPU 88%——速度锚点：长文档解析的成本被稀疏注意力压下来了。 【古书倒着念】文字全对、顺序反了，像背诗倒着背——结构解析强但阅读顺序对竖排右起排版仍需代码后处理。 【6.7GB装进A6000】33亿参数、6.7GB权重，本地一张专业卡跑得动——本地化部署的门槛锚点。 【skill即部署】把部署流程固化成skill推给AI agent，等于把”装模型”变成”发指令”——工具链思路的记忆点。

关键要点

  • 长文档连续解析是核心卖点
  • 原文引用：「最值得关注的能力，就是能够把几十页上百页文档连续解析，并保留跨页段落表格，还有版面结构」
  • 案例还原：UP主上传十页PDF，GPU占用88%、耗时39.7秒，抽查第一页、第二页和最后一页，提取内容全部正确，带索引序号的内容也成功还原。

  • 解读：对论文整理、书籍数字化、RAG知识库搭建者是刚需能力（30字内）。

  • 复杂表格按原结构输出

  • 原文引用：「严格按照了原表格中的这些结构」
  • 案例还原：用含多种复杂表格的PDF测试，第一页结构复杂的表格识别完全无误并保持原结构，第二份表格及剩余表格同样正确。

  • 解读：表格保结构比保文字更难，直接决定后续数据可用性。

  • 多语言+双栏排版可胜任

  • 原文引用：「在一个PDF页面中包含多种语言，而且分两列进行排版，它也都能完全正确的提取出来」
  • 案例还原：一份单页含日语、韩语、中文且分两列排版的PDF，日语部分、韩语部分、中文部分分别比对，均完全正确。

  • 解读：跨境资料、多语种档案处理场景的可行性信号。

  • 竖排古书：文字全对、顺序需后处理

  • 原文引用：「它只是将原始PDF中原本应该是从右向左的顺序，他直接按照从左向右的顺序进行了输出」
  • 案例还原：竖排繁体PDF比对后文字标点全对，但原书最后一句被输出为第一句；UP主建议用代码重新排序实现右→左输出。

  • 解读：古籍数字化项目必须预留排序后处理环节。

  • 第一版体验差、二代翻身（实测态度）

  • 原文引用：「我实测的体验感觉非常差，所以当时没有为大家发布测评视频」
  • 案例还原：UP主因一代体验差而放弃测评，二代实测后认定提升巨大才发布本期视频，并以逐级加难度的八个案例支撑结论。
  • 解读：提醒读者模型迭代快，旧印象不能代替新实测。

① 市场调研 & 用户研究

  • 新洞察：UP主用”前代体验差→不发测评→二代实测翻盘”的做法，示范了一种诚实的评测叙事：先交代基线，再展示提升，可信度来自对比而非单点吹捧。做产品/竞品评测时可借鉴”难度阶梯式测试设计”——从单页糊图→多页PDF→双栏→复杂表格→公式流程图→模糊扫描→竖排繁体→多语混排，每级只加一个变量，结论才有说服力。
  • 可借鉴方法：用参数面板（耗时、token数、GPU占用）量化体验，把”好不好用”变成”2.6秒/页、39.7秒/10页”这类可比较指标；把测试过程开源（GitHub Web UI），让结论可复现。
  • 被揭示的坑：只看模型榜单（趋势榜）不够，第一版就是反例；版式阅读顺序（竖排右起）这类”隐性需求”只有真实样本才暴露。

④ 智能硬件 PM（AI时代新定义）

  • AI真正发挥作用的阶段：本期信息集中在”文档理解”环节——OCR提取文字/公式/表格并恢复标题层级、版面位置、阅读顺序。对硬件PM而言，这对应的是把规格书、器件datasheet、认证文档、竞品拆解报告等资料批量结构化的能力（推论，视频未直接涉及硬件流程）。
  • 边界在哪里：视频明确暴露了边界——竖排右起阅读顺序输出反了，需代码后处理；也就是说AI能”读全”但未必”读对顺序”，结构化结果的校验与规则修正仍要人来兜底。视频没有任何关于ID图→MD堆叠→电子设计demo全流程的内容，不能据此推断AI可代劳这些环节。
  • 工具/流程信号：UP主把部署固化为 skill 推给 codex/workbody/cloud code/workbot 等 agent，说明”模型能力”正在被封装成”agent可调用的技能”，这提示PM未来评估工具时，要看它能否被接入agent工作流，而不只是单机可用（推论）。
