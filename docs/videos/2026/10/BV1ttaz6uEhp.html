核心内容（字数视视频长度而定，上不封顶）

1) 背景与使命：Build Your Own Intelligence（BYOI） - 背景：LangChain 在纽约 Interrupt 大会上将使命明确为「Enable every company on their intelligence」，主旨是帮助企业构建“自主可控”的智能体与智能体系统，不再被单一闭源方案绑定。 - 核心观点：落实 BYOI 的三大关键词是开放（Open）、复合/合成（Compounding/Component 合成效应）、治理（Govern/Governance）。开放确保“拥有权”（Own）在企业手里；复合是把提示词工程、上下文工程、工具/MCP、技能（SOP）与人机协同整合出“化学反应”；治理是把这场“化学试验”放进可控的实验室里（权限、审计、风控），避免野蛮生长后的反噬。 - 案例：视频明确指出开源模型与开源框架是企业“Own”的底座。典型落地路径是：采用可私有化的 LangChain/LangSmith + 开源模型，结合企业自有 SOP 技能包与工具接口（MCP/HTTP），把数据安全与权限都放在企业网关里统一治理，既享受生态活力，又不失控。 - 关键结论：要“拥有”并非只选私有部署，更要“开放组合 + 有界治理”，否则不是 Own，而是“重度依赖 + 黑盒风险”。

2) 人与流程：三类角色 + 智能体开发生命周期（ADLC） - 核心观点：组织层需要三层人协同：Platform Engineers（云原生/底座/网关/运行时）、Agent Engineers（用代码造智能体，含数据工程/科学家/多领域开发者）、Non-technical Builders（无代码构建者，借助 LangSmith Slate/Customer Apps 面向场景落地）。流程层强调 ADLC：Build-Test-Deploy-Monitor 的受控闭环，突出“快上生产、用真实数据驱动评测与进化”。 - 案例：一家内部客服团队的演进（视频方法论再现）。起因：Pilot 阶段只“Build 得很快”，但效果不可控。过程：引入 ADLC，Platform 工程师先搭运行时与模型网关、工具服务器、沙箱；Agent 工程师负责业务逻辑（指令/工具/技能/Hook）与评测集；Non-tech 人员用无代码 Builder 迅速铺设多个业务子场景。难点与弯路：早期“只做 Prompt”导致线上偏差难解释；引入 LangSmith 的 Trace/Trajectory 后，才用真实对话轨迹做根因分析、标注与回归评测。结果：从“写完就上”到“上了就评”，线上的轨迹成为持续改进燃料。 - 关键结论：智能体不是写完就行，核心竞争力在“测试-监控-评估-再训练”的后半场。

3) 运行时分层 + Deep Agent Harness：Agent = Model + Harness - 核心观点：运行时分三层：Business Logic（指令/工具/MCP/技能SOP/Hooks，强业务属性，常以文件+脚本打包）、Harness（除模型外的“外挂”与中间件，较通用，按模型能力厚薄不同）、Infra（运行时/工具服务/沙箱/模型网关）。Deep Agent Harness 提供：虚拟文件系统、Sandbox as a tool、人机协同（Human-in/on-the-loop）、Delegation（同步/异步/动态子智能体）等。 - 案例：代码智能体从“厚规划”走向“强委派”。起因：早期依赖复杂 Planner/To-do，慢且易偏。过程：切换到 Delegation 策略，主体智能体将子任务委派给子智能体，在沙箱中执行代码/脚本，虚拟文件系统集中管理上下文与产物；人类可在关键节点介入（Human-in-the-loop）。弯路：Planner 过厚导致成本与失败率上升；维护困难。结果：通过“沙箱即工具”精细控制执行安全与成本，整体性能更稳、可排障可审计。 - 关键结论：把“沙箱”当独立工具位，配合委派与人机协同，既能放权又能控边界。

4) 企业基建：工具服务器、记忆与模型网关 - 核心观点：企业智能体基建至少包括：可托管的 Agent Runtime、集中式 Tool Server（MCP/HTTP 工具聚合+统一权限）、Sandbox、模型网关（统一 OpenAI 风格 API、费用/配额、代理策略、Fallback、路由与安全护栏）。记忆方面先提供文件式记忆（Context Hub）与版本管理，小体量、可追踪、易审计，后续再上向量/结构化存储。 - 案例：多系统工具治理。起因：各团队私接工具，权限与审计碎片化。过程：沉淀统一 Tool Server，引入企业 SSO/细粒度权限与“服务侧权限+用户侧权限”双通道（Channels）模型；工具以 MCP/HTTP 统一暴露。结果：工具接入、权限管理与审计统一，智能体调用工具更稳可控。延伸：在模型网关内嵌入决策模型（System-1 型），做请求分流（强/弱模型）、工具触发与安全审查，兼顾成本与时延。 - 关键结论：Tool Server + 模型网关是一体两面，前者管“手”，后者管“脑”与“护栏”。

5) 观测与评测：决策模型 + Trajectory + Customer Apps + Engine V2 - 核心观点：评测与观测至少“半壁江山”。视频强调三件事： a) 决策模型（System-1 类）价值：更快更便宜，适配三类任务——评测（Eval：choice/score/boolean 输出契合指标）、护栏（Guardrail：内容与风险审查）、路由（Routing：模型/工具是否调用）。 b) LangSmith Trajectory：把 Trace 分析做成“对话式智能体”，支持根因分析、标注、聚合、自动化操作，降低理解和运维门槛。 c) Customer Apps：对话式生成“带界面”的 App，可分享与配套 Trace/分析，显著提升非技术人群的“造应用”与复用效率。 d) Engine V2（自进化引擎）：在“收集 Trace—生成数据集与指标—自动提 Issue/PR—人审—再部署”的自进化闭环基础上，增强了主动测试/攻击式探边能力、问题修复建议与费用优化（官方称成本下降约40%）；已扫描约7000万条 Trace，发现2万+ Issue（视频口径）。 - 案例：视频演示 Customer Apps 生成带界面应用（如数据分析助手），并与 Trace/评测打通；Engine V2 用真实轨迹驱动自动化回归，逐步逼近“上线即学习”的工程范式。 - 关键结论：智能体工程的“胜负手”在评测与监控，决策模型是把评测/护栏/路由“模块化”的关键零件，Engine V2 则把这套机制推向自运转。

记忆锚点（3-5条）

  • 【三板斧：开、拼、治】开源打地基，组合出化学反应，治理把实验装进安全玻璃房。核心逻辑：BYOI = Open + Compounding + Governance。
  • 【Agent=模型+外挂】“模型是引擎，Harness 是变速箱和外设”，强模型薄外挂，弱模型厚外挂。核心逻辑：业务逻辑+Harness+Infra 三层清晰分责。
  • 【沙箱是工具，不是枷锁】Sandbox as a tool，让代码执行可控、可溯源、可审计。核心逻辑：把执行权交出去，把边界收回来。
  • 【ADLC 闭环：先上生产再评测】Build-Test-Deploy-Monitor，真实轨迹反哺改进。核心逻辑：评测与监控是后半场，决定长期胜负。
  • 【决策三板：测、栏、路】System-1 决策模型三大落地：评测打分、护栏审查、路由分流。核心逻辑：更快更便宜，把判断从大模型里“拆”出来。

① 市场调研 & 用户研究

  • 新洞察/方法论：
  • 用 ADLC 让“线上真实轨迹”成为洞察主粮：部署更早、评测更晚但更真；用 Trajectory 做对话式根因分析与快速标注。
  • 决策模型用于“问卷与话术评测”：以 choice/score/boolean 自动打分，统一质检标准。
  • 可借鉴的调研方法：
  • 将用户访谈接入 LangSmith Trace，按标签聚合（渠道、用户类型、意图），用 Customer Apps 搭 UI 给业务方自助查询。
  • A/B 路由：决策模型把同一问题分流到强/弱模型，测质量-成本曲线，指导投产配比。
  • 常见坑：
  • 只看离线评测不看真实轨迹；只看平均分不看长尾失败。Trajectory+Engine 的“问题自动聚类+探边”能补齐长尾。
