Magpie：把所有订阅聚合起来

B站 · 黄益贺 · BV1Lyn96vEVv
cyan

一句话概括

一个网关把Codex、OpenRouter等分散订阅拧成一股绳，还能按问题难度自动换模型。

blue

核心内容

背景与定位 Magpie 是国内开发者做的一个工具，官方说法是「一个网关通吃所有的API」，UP主用更通俗的话解释为「个人用户的中转站」，核心逻辑就是把用户手上各种模型渠道「拧成一股绳」，统一进网关再输出给下游工具。UP主特别说明，这类需求此前常用的是国人开发的 cc switch，它较早实现了在 code 类工具里使用各种非 Anthropic 模型，而 Magpie 的价值在于「不需要再去做那些很复杂的设置」。

基本用法：把订阅和API接进来 Magpie 后台分几块：agent、provider、subscriptions、vendor。agent 这一栏，只要你本机已经装了某个 agent，在列表里打勾就能把它注入进去，UP主自己接入了 codex、work buddy、open code 三个（他平时在 ghost st 里用 open code）。provider 这一栏要填 API key，UP主接了三个渠道：OpenRouter（24个模型）、Codex（7个模型）、Work Buddy（15个模型）。此外还有 subscriptions 一栏可接 Cloud 等订阅类服务，以及 KIMI 官方已与 Magpie 合作的标识，页面上还单列了 partners/sponsors。UP主强调这块操作「很简单很简单」。

案例一：在 Work Buddy 里调用 Codex 订阅 UP主在 Work Buddy 的模型列表里看到，最上方是腾讯官方提供的混元、节月星辰、DeepSeek 等模型，下面接的是自定义模型（OpenRouter 一堆），再下面是 Codex 订阅。他选了 GPT-6.1 提问「你是什么模型」，从菜单栏可以看到：Work Buddy 发起请求 → 经过 Magpie 网关 → 最终使用 Codex 订阅的模型，回复明确说「我是 GPT-6.1 codex，在 Work Buddy 当中为你提供帮助」。整个过程无需复杂配置，这就是它的基础用法。

案例二：在 Codex 里反调用 OpenRouter 模型 反过来在 Codex 里，上方是官方模型，下方是 OpenRouter 接入的模型。UP主选了 OpenRouter 的 DeepSeek V4.1 Flash 问「你是什么模型」，从动画效果能看到 Codex 连接 Magpie 网关、再调用 OpenRouter 渠道。有意思的是，模型自称「我是 GPT-5」，但其实调用的是 DeepSeek V4.1 Flash——UP主借此说明网关确实在路由，只是模型自我描述不一定准确。

核心亮点：routing 路由规则（最有价值的部分） UP主设置了一个叫「easy or hard」的路由组，组里允许两个模型：Codex 订阅的 GPT-6.1、OpenRouter 的 DeepSeek V4.1 Flash。规则有两条：①用户要求编写/修改代码、修 bug、写测试、操作文件、联网研究、长篇写作、复杂分析等任务 → 调用 GPT-6.1；②简短闲聊、基础概念问答、一句话翻译 → 调用 DeepSeek V4.1 Flash。设置好后，这个路由组会作为一个「模型」出现在模型列表里，直接用就行。

案例三：路由实测——问「介绍一下HTML」 UP主发起提问后，Magpie 先用 DeepSeek Flash 判断意图，判断出这是简单问题，于是自动调用 DeepSeek 来回答。他的解释是：简单问题用复杂贵模型和简单模型，回复质量差不多，没必要花贵模型的钱。如果问的是编程类问题，就会自动切到 GPT-6.1。这构成了一个完整的语义路由闭环：意图判断模型便宜 → 分派到对应模型。

案例四：让 agent 帮你配置 Magpie 本身 UP主实际配置时的做法是：直接跟 Codex 说「我已经在本机安装 Magpie 了，看一眼官方 doc，研究下怎么做路由配置」，并把官方文档链接（Mac pad 点 AI 斜杠 Docs intent）发过去让它解释。Codex 告诉他 routing 是把多个模型包装成一个入口，意图规则由自己选模型；也可以命令行执行，如 magpie group add + 路由组名 + 反斜杠 + provider 名 + 模型名（多模型用英文逗号分隔）。他随后让 Codex 按「GPT-6.1 为主力、简单问答用 DeepSeek Flash」完成了配置。UP主总结出一个通用方法：看到新工具不知道怎么用，就把官方文档链接丢给任意 agent，它读取后基本都能解释给你听——「这是我经常使用的一个方法」。

关键结论 Magpie 由浅入深三层价值：①统一入口，省去每个工具单独配 key；②跨渠道互调，订阅和 API 打通；③智能路由，按任务难度自动选模型，兼顾质量与成本。UP主的态度是「很推荐大家去用一用，我觉得还是挺实用的」，并建议先用他这套配置感受一下。

记忆锚点

  • 【拧成一股绳】所有订阅和API像几股散绳，Magpie 是个绳结，下游工具只管拉这一根——对应「统一网关」的核心定位。
  • 【easy or hard 分流闸】简单问题走便宜模型，写代码走贵模型——语义路由就是闸机，按行李大小开不同的门。
  • 【先安检再登机】先用便宜模型判断意图，再决定上哪架飞机——意图判断与执行模型分离的两段式逻辑。
  • 【问路先给地图】不会用新工具就把官方文档丢给 agent——UP主反复验证的通用方法论。
  • 【模型会撒谎】问它是什么模型，它自称 GPT-5 其实在跑 DeepSeek——网关层路由才是真相，别信模型自述。

关键要点

  • 统一网关消灭重复配置
  • 原文引用：「他不需要再去做那些很复杂的一些设置了」「把所有渠道、所有模型渠道拧成了一股绳」
  • 案例还原：以往用 cc switch 这类工具需要在 code 类工具里做各种配置才能用非 Anthropic 模型；Magpie 里只要本机装了 agent，在列表打勾注入，provider 填个 API key 就完成接入，UP主一次接入了 codex、work buddy、open code 三个 agent 和三个 provider。

  • 解读：多订阅用户的第一痛点是配置成本，谁把配置变成「打勾」谁就赢。

  • 订阅与 API 可以互相顶班

  • 原文引用：「我在这里边也可以选各种各样模型，在 codex 里边上边是官方的模型，然后下边呢你看都是 open router 我接入的这些模型」
  • 案例还原：UP主在 Work Buddy 里用 GPT-6.1 提问，背后走的是 Codex 订阅；又在 Codex 里选 OpenRouter 的 DeepSeek V4.1 Flash，动画显示请求经 Magpie 转发到 OpenRouter 渠道。双向打通，两个工具都能看到全部渠道的模型。

  • 解读：渠道不再绑定工具，谁的订阅额度闲着就能被别处调用。

  • 语义路由是省钱的关键设计

  • 原文引用：「简单的问题自然就没有必要去使用复杂的贵的模型来回答了」「对于这个简单的问题回复质量是差不多的」
  • 案例还原：UP主配置「easy or hard」路由组：编程、修 bug、写测试、长篇写作、复杂分析走 GPT-6.1；闲聊、基础概念、一句话翻译走 DeepSeek Flash。实测问「介绍一下 HTML」，先由 DeepSeek Flash 判断为简单问题，随即用它作答；若问编程问题则切 GPT-6.1。

  • 解读：路由 = 意图分类 + 分派，把「贵模型做小事」的浪费砍掉。

  • 路由组会伪装成一个模型

  • 原文引用：「在模型列表里就会出现这样一个你设置好的这样一个路由的名字，它变成了其实变成了一个模型在这里边了」
  • 案例还原：UP主设置好 easy or hard 路由组后，它直接出现在 agent 的模型下拉列表里，使用体验和普通模型没有区别，用户不需要每次手动选择。

  • 解读：好产品把复杂规则藏在简单入口后面，降低使用心智负担。

  • 用 agent 读文档来学新工具

  • 原文引用：「这年头你如果看到一个新的工具不知道怎么使用的话，你就把官方的文档、官方的链接给到这个 agent 的，他基本上都会去读取了之后，他都会解释给你听的」
  • 案例还原：UP主把 Magpie 官方文档链接发给 Codex，让它解释 routing 机制，Codex 说明 routing 是把多个模型包装成一个入口、意图规则自行选模型，还给出 magpie group add 命令行写法（provider 名 + 反斜杠 + 模型名，多模型英文逗号分隔），最后按 UP主需求（GPT-6.1 主力 + DeepSeek Flash 处理简单问答）完成配置。
  • 解读：AI 时代的工具学习法从「看教程」变成「让 agent 读文档教你」，这也是 UP主反复推荐的方法。

三大职业视角洞察

gold

① 市场调研 & 用户研究

  • 新洞察：视频本身是一次「用户自述式需求访谈」——UP主作为多订阅付费用户（Codex 100美金、OpenRouter 长期使用、准备充 Work Buddy 会员），完整说出了痛点链路：订阅分散 → 配置复杂 → 想跨工具用模型。这是典型的「重度用户需求还原」，比问卷更真实。
  • 可借鉴的调研方法：让用户「边操作边解说」（UP主全程演示后台、路由设置、实测提问），比事后回忆更准确；尤其「菜单栏动画显示请求走向」这类可视化反馈，是观察用户理解系统行为的好窗口。
  • 被揭示的坑：UP主问「你是什么模型」，模型自称 GPT-5 实际跑的是 DeepSeek——用户对系统真实行为的感知并不可靠，单靠用户自述做调研会有偏差，需要像路由动画这样的客观证据交叉验证。

② 品牌推广 & 营销

  • 新思路：Magpie 的增长路径值得研究——开发者个人 IP（X 账号可直接对话）+ 与 KIMI 官方合作 + partners/sponsors 单列展示，形成了「开发者工具靠生态背书」的传播链。UP主在直播中多次引导「有问题去 X 找他」，说明开发者个人触达是这类工具信任建立的关键。
  • 值得研究的传播路径：闭门直播（仅知识星球成员）→ 录像放视频号 → 剪切片去废话，这是一套「社群先行、公开后置」的内容分发漏斗，切片化处理本身就是提升传播效率的手段。
  • 可留意的点：UP主用「拧成一股绳」这样一句大白话替代官方术语「一个网关通吃所有API」，说明工具类产品的传播语言要口语化。
cyan

③ 电商运营 & 渠道管理

  • 可参考的策略：Magpie 后台把渠道清晰分成 provider / subscriptions / vendor 三层，还显示每个渠道的模型数量（OpenRouter 24个、Work Buddy 15个、Codex 7个）——这种「渠道库存可视化」完全可以迁移到电商多渠道管理：把各平台库存、可售SKU数一屏呈现，运营才能判断该补哪个渠道。
  • 转化路径启示：视频里从「添加 provider 填 key」到「agent 下拉列表出现模型」再到「实测提问成功」，是一条极短的首次成功路径；UP主特别强调「很简单很简单」，说明降低首次上手门槛就是提升转化的核心。电商同理：新用户从注册到首单的环节越少越好。
  • 用户旅程新发现：路由组的「设置一次、长期自动」设计，对应电商的「规则化运营」——把重复判断（简单/复杂、高价值/低价值客户）交给规则引擎，运营只维护规则而非逐单处理。
