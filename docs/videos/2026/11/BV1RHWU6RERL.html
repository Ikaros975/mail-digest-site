Fable5.2实测，AI能接住一整件事了吗？

清华姜学长 · 2026-11-12
cyan

一句话概括

AI能接住一整件事了，但接住不等于交得出手。

blue

核心内容

UP主清华姜学长用最新发布的 Claude Fable 5.2 做了四组实测，核心追问是：任务拉长之后，模型能不能记住最初目标、能不能自己发现走偏、能不能舍得推翻已做部分、最后交出的东西拿什么证明能用。

测试一：故宫角楼网页（全程自检案例） UP主给 Fable 5.2 发了一段需求，要求做可旋转、可放大的故宫角楼网页，并特意交代”先查资料，别凭着印象去编”。一个多小时后模型交付，中间它自己截图检查，发现屋顶多了一块黑的，又回去改掉了。模型查了故宫博物院介绍、找了照片对照，还做对了一个细节：角楼四个方向屋顶并不完全一样，临护城河方向朝外是山面，沿城墙方向朝外是岩面——转动模型能看到区别。UP主点出关键：模型检查时有了”外部参照”，截图能帮它发现黑块，但建筑朝向和比例还得回资料核对。最后模型也交代了手工简化：一些高度是照图片估的，哪些有依据、哪些是近似，需要梳理清楚。

测试二：电路板设计（推翻重做案例） 过去模型常把一块板做到接近完成，剩下线路怎么都接不上——前面选的位置、方向和引脚到后面一起成了限制。Fable 5.2 这次会回头改这些选择：重新分配两颗芯片和引脚，让相关走线留在同一层避免交叉；另一处局部布线不理想，它会拆掉重布。UP主把它接上此前讲 ASTRA 的问题：长任务里模型要记住最初目标，同时允许自己推翻早先决定——一条线绕不过去，原因可能出在几步之前，关键能力是判断”继续绕还有没有意义”，还是退回换布局，即”能把已经做过的部分重新打开”。

测试三：会议扬声器（三维装配案例） 电路板直着放进外壳时，静音开关会撞到后面壳壁。模型在三维模型里检查后试出一个装法：先倾斜约25度把板子放进去，再转平，这个动作最后被写进了组装说明。UP主总结：电路得连对、零件得放得下、安装时还得有一条走得通的路径——设计电路板时就得兼顾后面怎么装，一个局部决定会一直影响最终装配。DAVID 的工程师制造组装并测试了三件能工作的原型，后续还需电气验证、天线调试、热测试；至少这次项目里，设计文件已经走到实物这一关。

测试四：表格工具与游戏（复杂软件与成本案例） MATTHEW BERMAN 让 Fable 5.2 做网页版表格：可点开单元格看公式、加载销售样表、用数据透视表汇总订单，版本做了将近50个小时。UP主选表格是因为它适合检验复杂软件能力：原始数据、单元格引用、计算结果和汇总表必须彼此对得上，改一个数字，引用它的结果也要更新——和此前 ASTRA 做 PPT 关心的问题相通：成品进入工作后还会被继续编辑、补充和复用，模型要考虑后续操作。另做一个战争机器风格游戏：能跑动、找掩体、开枪换子弹，倒地后队友会来救援，机制已在同一关卡配合起来，是”完完整整的一款游戏”；但项目跑了几天，截止录制按 API 标价估算费用约1.5万美元。UP主由此强调：模型能连续工作更久，意味着能完成更复杂的东西，也意味着等待时间、计算费用和最后检查要一起算进去。

系统比较：Remote Labor Index 该榜单收集240个真实外包项目，评审拿模型结果和专业人士原成品比对，看能否满足同一份需求。Fable 5.2 达标率41.3%，GPT-6 ARCIA 20.8%，Fable 5.1 17.9%。UP主解释数字含义：对应整件项目能否通过验收——做对九成步骤，但交出的文件打不开或关键结果有错，客户仍然用不了；长任务里前面每一步的成功都要保留到最后成品。5.2 提升明显，但仍有超过一半项目未达标，所以几段成功演示之后，还需要拿自己的工作去试。

结论：查依据、做第一版、检查发现前面的选择有问题、再回去重做——这些都算”一件事的工作量”。UP主说他提前要求了截图检查，但具体哪里出问题、该改哪一处，中间这些步骤模型自己处理了一轮。他坚持用同一标准看下一代模型（GPT、Claude、国内模型都算）：把事情交出去后，在哪些地方需要回来接手、哪些过去必须由人发现和安排修改的问题它现在能处理多少——“当中间这一轮返工也能交出去，我们才会在每天的工作里真正感受到模型更新带来的变化。”

记忆锚点

  • 【角楼转一圈】四个方向屋顶不一样，转个方向才看得见——模型检查必须有外部参照，截图能查黑块，查不了朝向比例。
  • 【线路绕不过去就拆板】一条线接不上，病根在几步之前——长任务的关键是敢把做过的部分重新打开。
  • 【先斜25度再转平】板子直着装不进去，斜着进再转平——局部设计决定一路影响最终装配。
  • 【表改一格，全家更新】改一个数字，引用它的公式和汇总都得跟着变——判断成品能不能用，看它能否被继续编辑复用。
  • 【41.3%的验收线】做对九步，最后文件打不开，客户照样不用——长任务的每一步成功都要保留到成品里。

关键要点

  • 模型要学会自我推翻
  • 原文引用：「一条线绕不过去，原因可能出在几步之前」「能够把已经做过的部分重新打开」
  • 案例还原：过去模型把电路板做到接近完成，剩余线路因前面选的位置、方向和引脚成了限制而接不上；Fable 5.2 会重新分配两颗芯片和引脚，让走线留在同一层避免交叉，局部布线不理想也拆掉重布。

  • 解读：评估长任务模型，要看它会不会返工，而不只看首版效果。

  • 检查需要外部参照

  • 原文引用：「他检查的时候有了一个外部的参照」
  • 案例还原：角楼测试中模型自己截图发现屋顶黑块并改掉，但建筑朝向和比例仍需回故宫博物院资料与照片核对；模型最后还主动交代哪些高度是照图片估的。

  • 解读：截图能查视觉瑕疵，事实准确性还得靠资料比对。

  • 局部决定会锁定最终装配

  • 原文引用：「一个局部决定，会一直影响最终的装配」
  • 案例还原：会议扬声器电路板直放会撞壳壁，模型在三维模型里试出倾斜25度放入再转平的装法，并写进组装说明；工程师据此做出三件可工作原型，后续还有电气验证、天线调试、热测试。

  • 解读：设计阶段就要把下游装配路径纳入约束。

  • 验收看整件交付，不看步骤完成度

  • 原文引用：「一件任务要做对九成的步骤之后，交出来的文件打不开或者关键结果有错，客户仍然用不了」
  • 案例还原：Remote Labor Index 240个真实外包项目，Fable 5.2 达标率41.3%，GPT-6 ARCIA 20.8%，Fable 5.1 17.9%——提升明显，但仍有一半以上项目未达标。

  • 解读：把AI产出当交付物评估时，”最后一步”的权重远大于中间九步。

  • 成本必须和结果一起算

  • 原文引用：「我会关心两件事情：他替我完成了多少工作，以及为了得到这个结果，我总共付出了多少」
  • 案例还原：网页版表格版本做了将近50个小时；战争机器风格游戏跑了几天，按 API 标价估算费用约1.5万美元。
  • 解读：长任务AI的经济账，要算等待时间+计算费用+人工检查三项。

三大职业视角洞察

gold

① 市场调研 & 用户研究

  • 外部参照方法论：模型自查靠截图发现黑块、但比例朝向必须回原始资料核对——这提示调研中”自动化发现异常”和”回到一手信源验证”是两道工序，不能合并。竞品分析同理：截图/抓取能发现表面差异，结构性差异（如角楼山面与岩面的朝向区分）必须回原始资料逐项比对。
  • 验收式评估思维：Remote Labor Index 用”能否满足同一份需求、能否通过验收”而非”完成多少步骤”来评分——这正是用户研究评估AI工具时应采用的标准：不问它能做几步，问最终交付物用户能不能直接用。
  • 避坑提示：模型会主动交代”哪些是依据、哪些是近似”——调研报告也应如此标注推断与事实的边界，这是可信度的来源。
red

② 品牌推广 & 营销

  • 演示≠可交付：UP主明确指出几段成功演示之后仍需拿自己工作去试——品牌方用AI做内容时，应把”演示效果”和”上线验收”分开评估，避免用 demo 标准要求生产标准，或用生产标准否定 demo 价值。
  • 成本叙事：一个游戏项目按 API 标价估算约1.5万美元、表格做了近50小时——营销内容中谈AI效率时，把”等待时间+费用+人工检查”一起呈现，比单说”一句话生成”更可信，也更符合用户实际体感。
  • 可复用性即传播力：UP主强调成品进入工作后还会被继续编辑复用——内容资产（表格模板、可交互网页）若设计成可二次编辑，传播生命周期远长于一次性成品。
cyan

③ 电商运营

  • 依赖关系意识：表格案例的核心检验是”改一个数字，引用它的公式和汇总结果也要更新”——电商运营中价格、库存、促销规则牵一发动全身，AI生成任何运营表/看板，验收时必须做”改一格测全链”的检查。
  • 装配路径思维：扬声器”倾斜25度放入再转平”的案例说明，局部选择会锁定最终装配——对应电商的履约路径设计：前端一个SKU/包装决策，会一路影响仓储、打包、物流环节，AI辅助设计时必须把下游路径作为约束输入。
  • 验收标准对齐：客户用不了=失败，不论中间做了多少——电商AI工具（详情页生成、客服话术、选品报告）的验收应直接对齐”能否上线使用”这一条，而非完成度百分比。
blue

④ 智能硬件 PM（AI时代新定义）

  • AI已真正发挥作用的阶段：本视频给出的实证集中在电子设计前期与结构装配验证——Fable 5.2 能重新分配芯片引脚、优化走线同层布局、在三维模型中试出倾斜25度装入再转平的装配路径并写入组装说明，且设计文件已走到实物（三件可工作原型）。这是”ID图→MD堆叠→电子设计前期demo”链条中，MD与电子设计交界处的明确信号。
  • AI的边界：查资料是否准确仍需人核对（朝向与比例回原始资料）；截图只能查黑块这类视觉问题；模型做出的简化（高度照图片估）需要人梳理清楚哪些有依据、哪些是近似；实物之后仍需电气验证、天线调试、热测试——物理验证与信源核实仍是PM必须亲自把关的两件事。
  • PM岗位职责演变的信号：UP主的判断标准从”AI做了多少”转向”哪些地方我需要回来接手、中间这一轮返工能不能交出去”——这意味着PM的新核心能力是定义验收标准、设计检查参照物（如提前要求截图检查）、核算长任务的总成本（等待+API费用+人工检查），而非自己完成每一步设计。

精彩原句摘录

  • 「他检查的时候有了一个外部的参照」（中段）——一句话点破AI自检的成立条件：没有参照物的检查只是自我感觉良好。
  • 「一条线绕不过去，原因可能出在几步之前……能够把已经做过的部分重新打开，这个才最重要」（中段）——长任务AI的能力分水岭，也是评估任何长流程自动化工具的核心指标。
  • 「一件任务要做对九成的步骤之后，交出来的文件打不开或者关键结果有错，客户仍然用不了」（中段）——把”步骤完成率”和”验收通过率”的差距讲得最清楚的一句，直接解释41.3%这个数字的重量。
  • 「当中间这一轮返工也能交出去，我觉得我们才会在每天的工作里真正感受到模型更新带来的变化」（结尾）——给出了判断AI是否真正进入日常工作的唯一诚实标准。
