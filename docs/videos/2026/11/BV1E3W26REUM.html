核心内容

背景：观测已成行业刚需，但形态四年未变

UP主沧海九粟（LangChain 与 OceanBase 社区大使）开场引用 LangChain 社区去年年末的调研数据：以海外为主的近千家公司和个人的反馈中，89% 的受访者表示已经在各种层面上开始使用 Agent 可观测性。到今年社区全球开发者大会（旧金山），两天近20个 speech 里约80%都会讲到具体评测——意味着海外公司已从”观测”演化到”评测驱动优化迭代”的阶段。UP主判断，国内今年有越来越多企业把 Agent 落到生产环节，如果还没用观测评测，现在正是切入的好时机。

他特别强调 LangChain 的资历：ChatGPT 是2022年11月左右出来的，LangChain 公司2022年10月成立，2023年1月就发布了 LangSmith——这是 LangChain 生态里唯一的闭源产品，专注智能体工程化。也就是说 ChatGPT 出来才两个月，一个覆盖大模型应用观测、评测的产品雏形已经存在。这让”观测+评测”从一开始就是全球最领先公司认定的必做之事。

观测的”四要素”：thread / trace / run / trajectory

UP主统一了业内众说纷纭的名词，归纳为四要素： - thread（也叫 session / conversation）：你和智能体在一个窗口里来回对话的整体，是最大的框； - trace：一组请求响应过程。他强调这跟云原生微服务的 trace 很不一样——微服务是毫秒级请求响应，”你如果上到秒级肯定是有问题的”；而 AI 领域”你那个任务不帮我一个小时内做完，我就得谢天谢地了”。AI 的 trace 里包含大量中间过程； - run（云原生里叫 span / observation）：一来一回过程中细粒度的工作输出，包括 streaming 输出。UP主解释 streaming 的必要性：互联网有”八秒原则”，Agent 不可能一小时才给答案，必须在差不多的时间内给反馈，这些中间输出都值得记录； - trajectory：把树状结构全部打平、去掉冗余元信息后的纯内容输出，更适合做数据分析和训练场景。

UP主给出的实操判断标准很干脆：选观测工具时，只要具备 thread、trace、run、trajectory 这四要素就基本够用。

问题诊断：工具”长得都差不多”，而且”太够了”

UP主现场展示了 LangSmith 最新界面，并直言”千篇一律”——LangSmith、LangFuse、Phoenix 大家源头都是 LangSmith，长得都差不多，”当年和现在唯一的区别就是 logo 变好看了”。更关键的洞察是：这套东西做了四年，那张树状图基本没变过，而它在云原生时代就有雏形了。

那它够用吗？UP主用的是逆向思维：问题恰恰在于”太够了，不但够，太多了”。他讲了一个自己的真实场景：社区小伙伴找他帮忙调试，他第一句话让对方把 trace 图发来，第二步点开 trace——先拉一下看有多长，如果很长就赶快先关上，调整一下呼吸，去搞杯茶，然后再点开来。他说即使自己对 LangSmith 非常熟，看到左侧的树特别长也心发慌。结论是：简单 trace 谁都能看，复杂一点的 trace 对专业开发者都是很大的负担。

三步解法：看得清、读得懂、改得好

UP主明确说这三点是”尝试”，不敢说是未来标准。先交代背景：Agent 观测的数据采集分两类入口——自建应用（用框架自研，行业内靠谱的 Agent 框架约15~20个，靠框架内提供的采集手段）和现成应用（Codex、Claude Code、Cline、Cursor 这类，通过 hooks 或本地写入文件采集）。两类采集方式不同，但大量企业里同时并存，平台都需要支持。

  • 看得清：树逃不掉，大应用必然得到大树，所以做”筛选”——把异常的、耗时长的、token 花费多的、特定工具调用的高价值节点筛出来，把大树变小树，降低心智负担，且筛选组合可保存。此处有两个要点：一是把 token 换算成钱，UP主说 token 不代表钱，很多 token 免费、很多很贵，他会帮用户算账，包括订阅制折算；二是 timeline 图和基于组织结构的架构图，他明确说这两种是辅助——几百行的 trace 里给你几十上百个节点，”你看得再漂亮的图对你来讲都是没有用的”。
  • 读得懂：针对”白屏困境”——筛选框给了一堆，用户根本不知道该勾什么。解法是把覆盖80%问题的核心要素直接露出：对话结构、MCP、记忆、skill、决策。具体做法是”一总一分”：trace 根层给总览（有哪些 MCP、调用几次、是否失败、总耗时），run 层单独开面板给细节，不影响原有细节查看。还解决了一个经典痛点：用户输入通常埋在某一层对话里，前面有一大串意图识别、预处理工作，平台把真正的用户核心输入提到根上，让人一眼看到输入与输出。对决策模型这类新概念，UP主说观测平台可以起辅助认知作用——他总结决策模型两大场景是评估评测和意图识别（意图识别里最常用的是模型路由和工具放行），输出是三要素 now、布尔值、choice/score，”只看 JSON 数据你一下看不明白，但画成图就好理解”。
  • 改得好：本质是轻量级在线评测，UP主叫它”诊断“——观测的人工延续。价值在于你睡觉后有个 AI 帮你采样、实时找关键点、发现问题再叫你，然后你去看的还是”看得清、读得懂”那套。他批评很多人跳过观测直接评测，”因为观测太难读懂了，索性让 AI 全部对付起来，给我一个数值，但那个数值真的保熟吗”。他给大模型评测划了一条及格线：必须有抽取 trace 结构体作为 rubric evidence 的能力，没这个功能实用程度非常低。他也解释为什么有了大模型还要 code evaluator：大模型花钱又慢，而判正则、写规则就能拿到零或一，”那为什么不做呢”。至于 agent as judge，他坦承 LangSmith 做了四年到现在没有，因为目前不算高价值功能，但未来一定会有，前提是沙箱技术成熟。最后他保留了一个”人工背锅”（人工复核确认）环节，强调人的经验性判断不可替代。

产品动向：基于蚂蚁观测团队和 OceanBase 开源社区，即将开源一个 Agent 观测与评测产品，涵盖上述三大能力；数据底座面向个人提供轻量级开源 Ceph（原文如此）、面向企业提供 OceanBase 分布式，未来还有 LakeBase。UP主强调观测评测对多数据融合非常重要。

记忆锚点

【四件套】thread 套 trace，trace 装 run，打平变 trajectory——观测工具的”入场券”，缺一别选。

【先关再开】看到长 trace 先关上、调呼吸、搞杯茶——四年未变的树状图，专业开发者看了都心慌。

【八秒原则】微服务按秒算问题，Agent 按小时算恩情——AI 的 trace 天生比云原生胖得多。

【token 换钱】token 不是钱，折成人民币才心疼——算账是观测的第一生产力。

【人工背锅】AI 判完你点确认——再智能的评测，最后一环还得人来担。

关键要点

  • 观测是评测的源头，不要跳过
  • 原文引用：「很多人会现在就会跳，因为现在很多人会跳过观测去做评测，为什么？因为观测太难读懂了，我索性让 AI 全部对付起来，给我一个数值，但那个数值真的保熟吗」
  • 案例还原：UP主在另一会场做分享时，同场五位老师有四位讲评测，只有他讲观测。他顺势点出行业现象：不少团队因为 trace 难读，干脆绕过观测直接跑评测拿分数，再用分数指导迭代。他的判断是这种捷径不可靠——评测要抽取 trace 结构体作为 evidence，源头数据不扎实，数值就没有保障；正确路径是先把观测做扎实，再做在线评测（诊断）。

  • 解读：提醒所有做 Agent 迭代的团队，评测的”保真度”取决于观测数据的质量，别本末倒置。

  • 观测工具只需四要素即可上手

  • 原文引用：「只要有这四个 thread、trace、run、trajectory 的基本要素，你就够用了，绝对够用了」
  • 案例还原：UP主展示 LangSmith 界面时，把 LangSmith、LangFuse、Phoenix 放在一起对比，指出大家”千篇一律”、源头都是 LangSmith，界面差异只是 logo 变好看。他给出的选型方法极简：不纠结界面美观或功能堆砌，先检查四要素是否齐全，齐全就基本能支撑未来业务；不齐全则要警惕工具能否跟上业务演进。

  • 解读：给正在选型的团队一条低成本、可执行的验收清单，避免被花哨 UI 误导。

  • 算账能力是观测的隐藏刚需

  • 原文引用：「很多 token 是免费的，很多 token 是很贵的，但是你花一点点其实很多钱……所以我们想着说，那别人不算，我们来算吧」
  • 案例还原：UP主举自己的例子：他在用 200 美刀的 Codex 订阅，一个月折算下来”对应的价格是用到 8 万人民币”，”1400 的东西用到 8 万，心里暗爽一下”。他据此设计产品逻辑：把 token 按模型定价折算成费用，订阅制先折成具体模型价钱，同时过滤掉免费 token，让个人用户和普通开发者知道”钱花在哪、耗时耗在哪”。

  • 解读：观测不只服务排障，也服务成本治理——对把 Agent 推向生产、要控预算的团队尤其关键。

  • 大模型评测的及格线是能抽取 trace 结构体

  • 原文引用：「你如果不能抽取 trace 结构体，把它作为评测的一个内容……如果你的评测体系没有这个功能，实用程度非常的低」
  • 案例还原：UP主在讲”改得好/诊断”时提出这条硬标准：rubric 可以自己写，但 evidence 必须从 trace 结构体里抽取。他把这条与 code evaluator 并列讲——有的大模型判断能用正则或规则代码判零一，就该用代码，因为大模型”花钱又慢”；agent as judge 虽被热议，但 LangSmith 四年没做，因为目前不算高价值功能，要等沙箱技术成熟后才可能落地，他提示关注后续彭飞老师关于沙箱的分享。

  • 解读：给评测体系设计者划出技术底线，避免做出”看似智能、实则不可用”的评测。

  • 人的确认环节不可省

  • 原文引用：「最终需要人的判断去确保你的……发现的这个 bug 是成立的……人工的复核和确认是必须要有的环节」
  • 案例还原：UP主提到与一位老师的交流：现在有种做法是完全不做观测、直接评测，但评测最后一定有一环”让你点个确认”。他把这个环节称为”人工背锅”（字面写”人工背锅”，读作背锅），并强调从实际价值看，人的经验性判断在观测系统里非常重要——机器可以采样、可以筛查异常，但 bug 是否成立、问题根因是什么，仍需人拍板。
  • 解读：人机分工的边界提示——AI 负责覆盖面与实时性，人负责定性判断与责任承担。

① 市场调研 & 用户研究

  • 新洞察：UP主引用的 89% 使用率调研、以及”开发者大会 20 个 speech 约 80% 讲评测”的观察，是判断一个技术品类成熟度的双指标法——问卷渗透率 + 顶级会议议题密度。做竞品分析时可直接借用：LangSmith、LangFuse、Phoenix 界面”千篇一律、源头都是 LangSmith”，说明这个品类的功能基线已经收敛，差异化空间不在主界面而在筛选、语义提炼、算账这些”体验缝隙”。
  • 可借鉴的方法：UP主的”逆向提问法”值得学——不问”这东西哪里不够”，而问”这东西是不是太够了”。他先承认四要素够用，再从”太长、看不懂、白屏困境”这些使用者的真实心理负担入手找需求。用户研究里，这是从功能清单转向心智负担的典型姿态。
  • 被揭示的坑：两个典型误判——一是把”图很漂亮”当成”有用”（几百行 trace 给几十上百节点，图再漂亮也没用）；二是跳过复杂环节直接要一个数值（”那个数值真的保熟吗”）。对应到用户研究，就是别被可视化仪表盘的精致感骗了，也别用单一打分替代过程理解。

② 品牌推广 & 营销

  • 新思路：UP主的整场分享本身就是一个开源产品的预热内容——先用调研数据建立品类共识，再用”四年没变”的历史叙事制造痛点共鸣，最后落在”即将开源”的产品上。这种”品类教育先行、产品发布收尾”的结构，非常适合技术产品的内容营销。
  • 值得研究的传播路径：他用极强的自嘲式场景做记忆点——“点开 trace 先拉一下多长，很长就赶快关上，调整呼吸，搞杯茶”，以及”200 美刀订阅用出 8 万人民币，心里暗爽”。这类具体、有画面、可转述的段子，比任何功能列表都更容易在社区里二次传播。品牌方可以学：把产品痛点翻译成用户的日常小剧场。
  • 差异化定位话术：他反复强调”别人不算，我们来算”（token 折钱）、”我们帮你总结”（决策模型三要素解读），把品牌角色定位成”帮用户做减法的翻译官”，而不是功能更多的工具箱。

③ 电商运营

  • 可参考的策略：把 token 换算成钱的”算账”能力，本质是成本透明化——对应电商就是让用户清楚每一笔花费去了哪里。订阅制折算成模型价格的做法，类似会员权益的”价值可视化”，让用户产生”我用 1400 换到 8 万”的获得感，这是提升续费与粘性的经典手法。
  • 转化路径启示：UP主讲 streaming 的”八秒原则”——用户等不到最终答案，必须在中间持续给反馈。电商用户旅程同理：从加购到支付的每一步都需要即时反馈与进度感，不要指望用户等到”最终结果”才被留住。
  • 用户旅程新发现：他把用户输入”从深层对话里提到根上”的设计，对应电商就是让用户一眼看到”我要什么、得到了什么”的对齐视图，减少在信息层级里迷路的挫败感；而”诊断”这种后台帮你盯异常、出问题才叫你的机制，可类比电商的异常订单监控与主动触达。

④ 智能硬件 PM（AI时代新定义）

本视频不涉及智能硬件、ID 设计、MD 堆叠或电子设计 demo，UP主全程讨论的是 Agent 软件层面的观测与评测，因此无法从逐字稿中提取硬件 PM 相关的工具或流程证据。唯一可迁移的间接信号是：UP主强调 AI 目前能承担的是”采样、实时找关键点、发现问题再叫你”这类筛查与提醒工作，而 bug 是否成立、根因判断仍需”人工复核确认”——这与硬件 PM 对 AI 的合理预期一致：AI 适合做初筛和信息提炼，最终决策与担责仍在人。除此之外不做延伸推论。
