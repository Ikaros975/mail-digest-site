核心内容

UP主“AI超元域”在谷歌上线 Gemini Carbon 模型当天，用 Antigravity CLI（推理级别 medium，模型标识写作 GMSSCARBBY）对 Gemini Carbon 连续做了 9 个复杂开发案例实测，并以自己前一天用 Cloud Fable 5.2 的测试结果为基准进行对照。视频开篇，UP主先澄清了一个背景：最近国内疯传的“国产3A大作射击游戏”实际是 Cloud 工程师开发的，国内流传版本只是把封面换成了自己的 ID，UP主称这种行为“还是挺可笑的”——这也是他强调要完整展示每个案例对话记录的原因：用可验证的记录说话。

案例一：像素风云端城堡。 同样的提示词昨天测过 Cloud Fable 5.2。结果两者效果“看上去相差无几，甚至风格非常像”。城堡可以切换黎明、傍晚、深夜，深夜时建筑灯光全部亮起，飞艇尾部还冒着烟，UP主评价“比昨天 Cloud Fable 5.2 效果还要更好”，云层也会飘动。但缺点立刻暴露：UP主摸电脑发现“有些烫手”，风扇开始转动，说明模型没有对游戏性能做优化。

案例二：模仿 Apple Music 风格的原生 macOS 音乐播放器。 模型先没加音乐，UP主追加要求加入演示音乐，之后在 Xcode 中打开并运行成功。界面非常接近 Apple Music：主题色跟随系统（切成亮色后播放器也变亮），有主页、歌曲列表、专辑、歌手、导入音乐、创建播放列表，播放效果“比较不错”，迷你播放器也不错。但出现了一个明显 bug：迷你播放器隐藏了时间，把界面拖大后时间依然不显示。UP主强调，相同提示词此前测其他大模型“基本都能做得比较完美”，这次 Gemini Carbon 却出现遮挡时间的 bug，据此判断其编程能力与 OS5.5、Cloud Fable 5.2 有差距。

案例三：为 Unity3D 开发射箭手角色。 对照物是此前 Cloud Ops 5.5 的版本：面部细节很好、能拉弓射箭、走路自然。Gemini Carbon 版本整体“还算可以”，但放大后问题密集：眼球突出、嘴突出，走路僵硬呆板，拉弓时弓箭变形，手指嵌进弓身。UP主结论：“跟 Cloud Ops 5.5 实现的效果相差太大了。”

案例四：用格斗四游戏引擎开发侏罗纪时代《我的世界》式沙盒游戏。 游戏运行起来“非常简陋”，地面和树木不如其他模型。加特林射击恐龙效果尚可，转速和音效都在，打方块、挖坑也能用。但关键短板是地图无法无限加载：走到边界就停了，而其他模型都能无限探索。UP主判断，Gemini Carbon 在“比较复杂的游戏开发”上“捉襟见肘”。

案例五：根据室内平面图还原 3D 可探索房间。 俯视查看后进入探索，整体尚可，但地板、家具、墙体颜色“融为一体”。更严重的是上二楼楼梯走到某位置“就走不动了，然后就会掉下来”，UP主称这是“非常大的 bug”。同时电脑开始烫手、风扇呼呼转——还原了 3D 空间却没做性能优化。

案例六：复刻巴塞罗那圣家堂。 对照昨天的 Cloud Fable 5.2 版本，Gemini Carbon 版“外观非常简陋”，进入内部后玻璃效果也一般，而 Cloud Fable 5.2 有“非常完美的光影效果”和彩色玻璃。UP主称差距“非常明显”。

案例七：3A 级射击游戏。 对照 OS 5.5 版本（枪械真实、效果很好），Gemini Carbon 版的枪“非常简陋”，且角色不动时“无论怎么打都不会被打死”，UP主认为这种 bug“不该存在”。

案例八：复刻小说《极光号》中的宇宙飞船。 外观“还算可以”，左侧位置可点击查看，但进入飞船内部后建筑“设计得非常简陋”；探索不到一分钟电脑就呼呼发烫。

案例九：超大质量黑洞吞噬恒星动画。 黑洞撕裂恒星、恒星物质汇入吸积盘，UP主评价“看上去还是挺震撼的”，是九个测试中完成得比较好的一个——但缺点依旧是电脑发烫、风扇狂转。

总结结论：Gemini Carbon “好像并不如官方宣传的这么厉害”，与 OS 5.5、Cloud Fable 5.5 仍有很大差距。需要说明的是，本次所有对照结论均来自 UP主自己前一日/此前的同题测试，属于单一评测者的主观横向比较。

记忆锚点

  • 【烫手的成绩单】九个案例全部跑完，电脑先“抗议”——视觉过关不等于工程过关，性能优化是模型的隐形短板。
  • 【播放器丢时间】UI 形似 Apple Music，时间却被吞掉——UI 复刻看皮相，细节 bug 看功力。
  • 【射箭手的手指】手指嵌进弓身、弓箭变形——“能生成”与“能正确形变”之间隔着一个档次。
  • 【走不到的二楼】楼梯走到一半掉下来——3D 空间不是画出来就行，碰撞与导航是硬门槛。
  • 【打不死的敌人】角色不动就永远打不死——逻辑闭环缺失，再炫的画面也撑不起“3A”。

关键要点

  • 性能优化是普遍短板
  • 原文引用：「他并没有对游戏的性能做优化」「我的电脑开始烫手，然后风扇呼呼的转」
  • 案例还原：云端城堡运行后电脑发烫；3D 房间探索中风扇狂转；极光号飞船探索不到一分钟就开始发烫；黑洞动画效果震撼但电脑同样发烫。九个案例中多数出现发烫，UP主据此推断模型“好像不会优化这种项目的性能”。

  • 解读：评估代码模型不能只看“跑出来的样子”，还要看运行时开销，对做 demo 评审的人尤其重要。

  • 原生应用能跑通，但细节会翻车

  • 原文引用：「这次 GEMINI4carbon 它竟然会出现这种遮挡时间的这种 bug」
  • 案例还原：macOS 音乐播放器在 Xcode 中运行成功，主题跟随系统、页面结构完整、播放与迷你播放器均可用；但迷你播放器隐藏时间，拖大界面也不显示。UP主指出相同提示词下其他大模型“基本都能做得比较完美”。

  • 解读：复杂 UI 的验收要看边界状态（缩放、迷你模式），别被首页截图骗过。

  • 3D 与游戏是分水岭

  • 原文引用：「在完成这种比较复杂的游戏开发的时候，他的能力就有些捉襟见肘了」
  • 案例还原：沙盒游戏走到边界无法无限加载；射箭手面部眼球嘴突出、拉弓变形、手指嵌入弓身；3D 房间上二楼卡住掉落；圣家堂外观简陋、玻璃光影远逊 Cloud Fable 5.2；3A 射击游戏枪械简陋且敌人打不死。

  • 解读：凡是涉及物理、碰撞、无限加载、骨骼动画的任务，都要预留人工兜底与验收环节。

  • 也有高光：视觉氛围类任务完成度好

  • 原文引用：「这也算是这几个测试题中，他完成的比较好的一个测试题」
  • 案例还原：黑洞吞噬恒星动画中，恒星被撕裂、物质汇入吸积盘，UP主称“看上去还是挺震撼的”；像素城堡的昼夜切换、飞艇冒烟、云层飘动也被评价“比昨天 Cloud Fable 5.2 效果还要更好”。

  • 解读：偏“视觉演出”而非“交互逻辑”的任务，是该模型相对擅长的区间（此为基于案例的推论）。

  • 用完整对话记录对抗造假

  • 原文引用：「所以我会展示每个测评案例的这种完整对话记录」
  • 案例还原：UP主开场提到国内疯传的“国产3A射击游戏”实为 Cloud 工程师开发、封面被换成他人 ID，称“这种造假行为还是挺可笑的”，因此每个测试题在 Antigravity CLI 中都保留完整测试记录供核查。
  • 解读：AI 能力宣传满天飞的时代，可复现的原始记录比结论本身更有说服力。

① 市场调研 & 用户研究

  • 本视频提供了一套可借鉴的“同题对照实验”方法：固定提示词、固定工具（Antigravity CLI）、固定推理级别（medium），只更换模型，并保留完整对话记录，这与用户研究中的控制变量 A/B 测试思路一致。
  • 评测维度不只看“能不能做出来”，还看细节正确性（时间显示、手指形变、碰撞掉落）、边界行为（无限加载）与运行成本（发烫、风扇）——提示做产品评测时要把“隐性成本”纳入指标体系。
  • 被揭示的坑：单看成品截图会严重高估模型能力；不看对话记录就无法排除“封面造假”式的宣传失真。
