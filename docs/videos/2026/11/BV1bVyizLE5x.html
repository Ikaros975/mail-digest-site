核心内容

背景：四倍价的“同芯兄弟”与不动声色的阉割

视频开篇摆出一组对比：RTX 4090 首发价 1599 美元，同代专业卡 RTX 6000A 首发价 6800 美元，是前者四倍多，而两张卡用的都是 AD102 核心。出厂屏蔽后，4090 保留 512 个 Tensor Core，RTX 6000 保留 568 个。按核心数推算，4090 的算力应是 RTX 6000 的 90% 左右——玩游戏确实差不多是这个水平。但用 4090 跑 AI 模型，只能发挥出大约一半的算力。差价四倍、硬件规模接近，为什么 AI 性能差一倍？UP 主把答案落在了一个非常具体的地方：累加精度模式。

原理层：FP16 负责乘、FP32 负责加，限制就卡在“加”上

大模型最繁重的计算是矩阵乘法：几千对数字两两相乘，再把乘积加到一起。Tensor Core 专门干这件事。相乘一般用 16 位浮点 FP16，快且省显存，缺点是最大只能表示到 65504；而几千几万项累加在 AI 计算中非常常见，结果很容易接近甚至超过 65504，即便不溢出也会带来很大精度损失，所以累加这一步要用 FP32（最大可表示到 3.4×10³⁸，比 FP16 大三十多个数量级）。英伟达的限制正设在这里：4090 的 Tensor Core 只有用 FP16 累加才全速运行，一旦切到 FP32 累加，硬件就主动降低指令发送速度，让 Tensor Core 干一拍歇一拍，速度直接减半。

关键是这个限制“精准避开了玩家”：游戏画面渲染用的是 CUDA Core，大部分游戏根本不用 Tensor Core，更不用它做 FP32 累加，所以臭打游戏的基本无感。数字上，白皮书口径是 4090 的 FP16 累加算力 330 TFLOPS，FP32 累加只剩 165 TFLOPS；而 RTX 6000 两种模式都是 364 TFLOPS。

破解层：四道锁，一道一道撬

第一道锁是“改寄存器”。显卡核心中有一个软件开关叫速度选择寄存器，每次通电初始化为固定值，让 32 位累加跑半速；但为调试方便，它允许被写入新值。想自己写程序改？不行——GPU 内部有 level 0 到 level 3 四级硬件权限，CPU、主板在 GPU 眼里都是外部设备，只有最低的 level 0；速度选择寄存器锁在 level 3，CPU 发来的修改指令会被忽略。唯一持有 level 3 的是 SEC2 安全核心。

第二道锁是“改驱动喂假程序”。安全核心上跑的程序并不固化在芯片里，而是进系统加载驱动时由 CPU 传过去的，看似可以 root 后塞个假程序让它改寄存器——但安全核心会验证数字签名，只认英伟达自己写的程序，塞假的直接黑屏。

第三道锁被 2026 年 6 月的研究人员撬开：安全核心对外接口中，有一个在把 CPU 传来的参数拷进堆栈缓冲区时没有检查长度，传入超长参数即造成缓冲区溢出。UP 主用一段伪代码讲清了原理：mailbox 函数接收 CPU 数据（data 指针 + data_size），交给 handle 方法，handle 在堆栈上申请固定 128 字节 buffer，然后把用户数据整段拷进去。buffer 是固定 128 字节，data_size 却由 CPU 控制——超过 128 字节，拷贝就会一路往后覆盖，最终覆盖到返回地址。返回地址记录 handle 执行完该从哪里继续；而 data 内容同样由 CPU 控制，于是攻击者既能改返回地址、又能决定改成什么，把返回地址指向一段修改速度选择寄存器的代码，安全核心就会“帮”着把寄存器改好。UP 主明确说明这是简化版原理，真实利用还涉及 stack cookie、ROP 技术等，并留了“可以单独做一期”的口子。

第四道锁是“改完怎么不退化成死机”。这类 ACE（任意代码执行）漏洞英伟达自然会补，最新驱动已无此漏洞。GPU Unlock 的做法是：打包老版安全固件，在真正的驱动加载之前先把它传给安全核心，触发漏洞把 32 位累加改成全速；此时不能直接退出，否则操作系统再加载新驱动会因显卡已被初始化而冲突死机。于是它向 PCIe 插槽发送软复位指令，命令显卡复位——不切断电源的前提下让 GPU 和安全核心状态归零，新驱动得以正常加载。而“不知英伟达硬件工程师出于什么考虑”，软复位并不改变速度选择寄存器的状态：复位后官方驱动正常加载，把新版引导固件传给安全核心初始化，因为通电默认就是半速、英伟达写新固件时也没去碰这个寄存器，全速档位就这样被保留了下来。

结果层：纸面翻倍，实测 15%–35%

白皮书口径下，解锁后 4090 的 FP32 累加算力从 165.6 TFLOPS 涨到 331.6 TFLOPS，正好翻倍。但实测跑真实 AI 任务（ComfyUI 生图、模型微调）一般只快 15%–35%，原因有二：一是 4090 默认 450 瓦功耗上限，显存和其他电路都在耗电，Tensor Core 速度翻倍后很容易撞功耗墙自动降频——同样存在漏洞的 30 系因核心少、耗电低、离功耗上限余量大，能快 25%–55%；二是 AI 计算不止矩阵乘加，大量时间花在数据于显存与计算核心之间搬运，瓶颈在显存带宽，Tensor Core 翻倍解决不了。但无论如何，4090 上算是白捡了 20% 上下。

覆盖面：目前支持 RTX 20/30/40 三代游戏卡；原版跑在 Linux，社区很快做了 Windows U 盘引导工具，进系统前完成解锁。50 系同样 32 位累加减半，但首发固件没有这个漏洞、硬件也不兼容老卡旧固件，用不了这套办法。

收尾层：封堵的两条路与一个哲学尾巴

封堵方案一：改新版驱动里的引导固件，让安全核心初始化时顺手把寄存器改回半速——但只拦得住用新驱动的人，退回旧驱动照样全速，治标不治本。治本方案是一次性物理熔丝（OTP Fuse）：一个物理上只能增大的计数器，用来记录固件最低版本，加载固件时比对当前版本与熔丝记录，即可发现是否加载了老版固件；装过一次新驱动、调高版本后，老固件就再也用不了。UP 主指出手机、游戏机等可升级电子设备普遍用这招防降级，但那些是整体设备、正常使用本就没有降级机会；显卡作为一个部件这么做“很容易引发争议”——我用的老系统不支持你的新驱动，装老驱动怎么就不行了？把显卡卖了别人没新驱动还用不了了？他明确说这“不属于技术范畴，这里就不讨论了”。

最后是一段带情绪的自嘲式总结：台积电一群人绞尽脑汁让芯片快一点点，英伟达想方设法让同一块芯片慢下来，又不知从哪儿冒出一群黑客顺着漏洞把速度改回去——三波绝顶聪明的人折腾一圈，回到原点；而且熬那么多日夜只换来 20% 提速，算不上划算买卖。到了 5nm，门越关越严、接口越藏越深，藏在后面的东西却越来越少，他称之为“所有电子产品的宿命”，并以“锁还在那里，而锁芯弹开的清响，足以让人感到最纯粹的快乐”收束全片。

记忆锚点

【干一拍歇一拍】Tensor Core 被指令成“干一拍歇一拍”，FP32 累加就只剩半速——限制不是砍核心，是抽走节奏。 【四道门】寄存器锁在 level 3、安全核心只认签名、接口不查长度、软复位不清寄存器——四道门依次被撬，最后一道竟是工程师“没碰”。 【128 字节的杯子】buffer 是固定 128 字节的杯子，data_size 却是 CPU 说了算的水量，水多了就漫到“返回地址”这层地板上。 【治标与治本】改驱动是换一把临时锁，OTP 熔丝是只增不减的计数器——一个能退回旧驱动，一个装过新版就再也回不去。 【纸面翻倍，到手两成】白皮书上 165.6→331.6 TFLOPS，实测只快 15%–35%，因为功耗墙和显存带宽在两头设卡。

关键要点

  • 限制的位置极其精准：只打 AI 累加，不打游戏
  • 原文引用：「4090 的 Tensor Core 只有用 FP16 进行累加才是全速运行，而一旦切换到 FP32 累加模式，4090 就会主动降低硬件指令的发送速度，让 Tensor Core 干一拍歇一拍，速度直接减半。」
  • 案例还原：AI 计算是“FP16 相乘 + FP32 累加”的组合，累加项动辄几千几万，结果易超 FP16 上限 65504，所以累加必须用 FP32；英伟达就把半速模式绑在 FP32 累加上。对比数字：4090 FP16 累加 330 TFLOPS、FP32 累加 165 TFLOPS，RTX 6000 两种都是 364 TFLOPS。而游戏用 CUDA Core 渲染、基本不碰 Tensor Core，因此“臭打游戏的”完全不受影响。

  • 解读：硬件规格表上的“算力”是模式相关的，看 benchmark 前先问跑在哪种精度下。

  • 权限墙：CPU 在 GPU 眼里只是 level 0 外部设备

  • 原文引用：「在 GPU 看来，CPU 也好，主板也好，都算外部设备，只有最低的 level 0 权限……而速度选择寄存器被锁在 level 3 权限下。」
  • 案例还原：UP 主先设想“自己写程序改寄存器”，被权限体系挡回；再设想“root 系统、用 CPU 塞个假程序给安全核心”，被数字签名验证挡回——发假程序显卡直接黑屏。能拿到 level 3 的只有 SEC2 安全核心，而它运行的程序是进系统加载驱动时由 CPU 传过去的，这个“传递”环节就成了攻击面。

  • 解读：芯片内的权限分层 + 签名验证，是把“硬件后门”变成“不可改”的标准配方。

  • 缓冲区溢出：可控的 data + 可控的 size = 可控的执行流

  • 原文引用：「如果 data size 超过 128 个字节，那么这个拷贝操作就会超过 buffer 的上限，一路往后覆盖，最终覆盖到所谓的返回地址。」
  • 案例还原：2026 年 6 月研究人员发现安全核心某个接口拷贝 CPU 参数进堆栈缓冲区时不检查长度。UP 主用伪代码还原：mailbox 收到 data 指针与 data_size → 传给 handle → handle 在堆栈申请 128 字节 buffer → 整段拷贝；data_size 由 CPU 控制，超过 128 即溢出到返回地址，而 data 内容也由 CPU 控制，于是返回地址可被改写成“修改速度选择寄存器的代码”，安全核心便替攻击者改好了寄存器。UP 主注明真实利用还涉及 stack cookie、ROP 等技术，此处只讲最基本原理。

  • 解读：漏洞不神秘，本质是“长度没校验”+“内容和长度都听外部人的”。

  • 软复位不清寄存器：一次“没碰”留下的全速档

  • 原文引用：「不知英伟达的硬件工程师出于什么样的考虑，这个软复位并不会改变速度选择寄存器的状态，它还是我们之前利用漏洞改过的值。」
  • 案例还原：改完速度后不能直接退出，否则新驱动加载会与已初始化的显卡冲突死机；GPU Unlock 向 PCIe 插槽发软复位，让 GPU 与安全核心状态归零而不切断电源，官方驱动正常加载、把新版引导固件传给安全核心初始化；由于通电默认半速、新固件也没去碰速度选择寄存器，之前改出的全速档位被完整保留。整个链条完整闭环：老固件触发漏洞 → 改寄存器 → 软复位 → 新驱动正常跑在全速上。

  • 解读：安全设计里“默认值假设”是最容易被利用的缝隙——默认半速，于是没人去显式设半速。

  • 纸面翻倍 ≠ 到手翻倍：功耗墙与显存带宽两道闸

  • 原文引用：「实测跑真实的 AI 任务，比如用 ComfyUI 生图或者做模型微调，4090 一般只会快 15% 到 35%。」
  • 案例还原：两个原因——4090 默认 450 瓦功耗上限，Tensor Core 翻倍后极易撞功耗墙降频；同漏洞的 30 系因核心少、耗电低、余量大，能快 25%–55%。另一原因是数据在显存与计算核心间搬运的时间瓶颈在显存带宽，Tensor Core 再快也解决不了。白皮书理论值则是 165.6 → 331.6 TFLOPS。

  • 解读：任何“算力翻倍”宣传，都要追问供电与带宽是否同步跟上。

  • 封堵：治标改固件，治本熔丝，但熔丝有争议

  • 原文引用：「真正治本的方法是使用一次性物理熔丝……由于 OTP Fuse 只能增大，所以只要装过一次新版驱动，调高版本之后，老版驱动里的固件就再也用不了了，漏洞自然也就堵上了。」
  • 案例还原：改新版驱动里的引导固件、初始化时顺手改回半速，只能拦住新驱动用户，退回旧驱动仍可全速，治标不治本。OTP Fuse 记录固件最低版本，加载时比对，版本只增不减，装过新版即封死老固件。UP 主指出手机、游戏机等可升级设备普遍用此法，但它们是整体设备、正常使用无降级机会；显卡作为部件这么做“很容易引发争议”——老系统不兼容新驱动怎么办、二手卡买家没有新驱动怎么办，并声明这已不属于技术范畴。
  • 解读：防降级机制在“整机”里是安全，在“部件”里就变成对用户处置权的侵犯。

① 市场调研 & 用户研究

  • 新洞察：同一颗芯片被切成两个市场，“规格表不等于真实能力”。 视频揭示 4090 与 RTX 6000 同核不同价（1599 美元 vs 6800 美元，Tensor Core 512 vs 568），名义算力差 10%，AI 实跑差约一倍。做竞品分析时，只看参数表会得出“4090 性价比碾压”的错误结论，必须回到“在什么精度模式下跑什么任务”这一层。
  • 可借鉴的方法：把“限制”当作研究对象，而不是背景噪音。 UP 主的路径是：先看官方白皮书数字（330/165 TFLOPS vs 364/364），再用真实任务实测（15%–35%），最后解释差距来源（450 瓦功耗墙、显存带宽）。这套“纸面→实测→归因”的三段式，正是用户研究中“宣称行为 vs 实际行为”差距分析的模板。
  • 被揭示的坑：用户自述的“性能不够”往往是错的归因。 真实瓶颈可能不在算力，而在显存带宽或功耗墙；30 系能快 25%–55%、40 系只快 15%–35%，恰恰因为两者余量不同。做深访时若只问“快不快”，会错过真正的约束条件。

② 品牌推广 & 营销

  • 新思路：官方“阉割”与民间“解锁”的对抗本身，就是持续免费的话题素材。 一个开源项目让 20–40 系跑 AI 翻倍，天然具备“黑科技、反权威、白捡性能”三重传播钩子；视频结尾“三波聪明人折腾一圈回到原点”的叙事，把技术事件升维成行业寓言，这是内容营销中典型的“把参数故事讲成人话”。
  • 值得研究的传播路径：社区接力。 原版项目跑在 Linux，社区很快做出 Windows 的 U 盘引导工具——开源项目 → 社区适配 → 降到普通用户可操作门槛，这条链路值得复盘：谁在传播、在哪一步降低使用门槛、什么节点形成话题峰值。
  • 风险启示：厂商封堵会引发争议，品牌沟通要预判“部件 vs 整机”的认知差。 OTP 熔丝方案在手机、游戏机上被普遍接受，但用到显卡这种“部件”上，UP 主直接点出“老系统不兼容新驱动怎么办、二手卡怎么办”的争议。任何以“防降级”为名的策略，一旦剥夺用户回退权，就会把技术问题变成公关问题。

③ 电商运营

  • 可参考的策略：把“可解锁/可回退”做成 SKU 卖点分层。 视频给出的硬信息是：20/30/40 系可解锁，30 系实测收益最高（快 25%–55%），40 系 15%–35%，50 系因首发固件无漏洞且硬件不兼容旧固件而完全用不了。对二手卡与整机渠道，这意味着不同代际的实际价值差异远大于参数表，定价与推荐逻辑应据此重排。
  • 转化路径发现：门槛即漏斗。 原版 Linux 方案 → 社区 Windows U 盘引导工具，使用门槛的每一次下降都会放大潜在用户池；同理，驱动版本会成为新的转化变量（装新驱动降速、退旧驱动恢复全速），售后与客服必须准备“驱动版本—性能表现”的对应话术。
  • 用户旅程新发现：复位与回退是信任节点。 软复位保留全速档位的细节说明，用户最在意的不是“怎么破解”，而是“改完会不会死机、能不能退回”。任何提供“增强/解锁”类服务的运营，都要把可逆性写进承诺，否则一次死机就足以摧毁信任。

④ 智能硬件 PM（AI 时代新定义）

  • AI 能在哪一步真正发挥作用的信号：本视频没有讨论 AI 辅助 ID 设计、MD 堆叠或电子设计 demo，不能据此下结论。 逐字稿唯一提供的是“AI 负载”这一侧的硬事实：真实 AI 任务中，矩阵乘加之外还有大量时间花在数据于显存和计算核心之间搬运，瓶颈在显存带宽；同时 4090 默认 450 瓦功耗上限，算力翻倍后很容易撞功耗墙降频。这两条对 PM 的启示是：做 AI 硬件规格定义时，算力、带宽、功耗三者必须同框评估，单点翻倍的纸面收益会被另外两项吃掉，实测只剩 15%–35%。
  • AI 的边界（推论，非视频原话）：视频展示的整条链路——权限分层、签名验证、长度校验、软复位语义、OTP 熔丝版本策略——全是“人做的决策”：把寄存器锁在 level 3 是人定的，只认自家签名是人定的，复位不清寄存器也是人定的。这些安全与产品边界的取舍，恰恰是 PM 最难外包的部分；AI 可以帮忙查资料、写验证脚本，但“要不要给用户回退权”“要不要用一次性熔丝”这类涉及用户处置权与争议风险的判断，仍然是 PM 的活。
  • 岗位职责演变的信号：UP 主一句“我把显卡卖了，别人没有新驱动还用不了了”，把技术方案直接翻译成用户权利问题。这提示智能硬件 PM 在 AI 时代的新定义里，必须同时握住两根线——硬件安全策略（签名、权限、熔丝）与用户可逆性（降级、二手流通、兼容老系统）；只懂前者会做出“技术正确、用户愤怒”的产品。

精彩原句摘录

  • 「台积电一群人绞尽脑汁，好不容易让芯片又快乐那么一点点，英伟达则想方设法让同一块芯片慢下来。最后呢，又不知道从哪儿冒出来一群黑客，顺着漏洞硬是把速度又改了回去。」（结尾）——一句话概括了整条产业链的利益错位，是全片最好的“记忆钩子”。
  • 「三波绝顶聪明的人折腾了一圈，结果回到了原点。」（结尾）——把技术攻防升维成对行业效率的冷幽默判断，适合作为任何“内卷式研发”讨论的引子。
  • 「因为锁还在那里，而锁芯弹开的清响，足以让人感到最纯粹的快乐。」（结尾）——解释了为什么这类“不划算”的破解仍有人做：动机不是收益，是破解本身。
  • 「治标不治本。」（中后段，谈改固件封堵时）——四个字给出了任何“补丁式封堵”的通用判据：能否被退回旧版本绕过。
